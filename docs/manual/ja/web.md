# snowpea web

`snowpea web` はエージェントをブラウザで開きます。snowpea IDE と同じ画面 — 同じサイドバー、会話、トラジェクトリ(Trajectory)、ドック — をローカルのデーモンが配信するので、追加でインストールするものはなく、データがあなたのマシンの外に出ることもありません。

```bash
snowpea web            # start the daemon if needed, print the address, open it
snowpea web --no-open  # print the address only
```

アドレスは `http://127.0.0.1:<port>/web/?token=…` の形です。トークンはデーモン自身のもの(`$SNOWPEA_HOME/daemon.json` にあるもの)で、ページはそれをそのブラウザタブに保持し、アドレスバーからは取り除きます。トークンを持つ人は誰でもエージェントを操作できるので、アドレスをチャットやチケットに貼らないでください。このアドレスはデーモンが動いているマシンでしか開けません。

## 別のマシンから

いちばん簡単なのは今も ssh トンネルです。ほかに待ち受けるポートはなく、接続も暗号化されます。

```bash
ssh -L <port>:127.0.0.1:<port> host
```

同じネットワークのノートPCやスマートフォンから直接開くには、リモートアクセスを有効にします。ユーザー名とパスワードで守られた二つ目のリスナーで、ループバックのリスナーはこれまでどおり動きます。

1. `settings.json` にユーザー名(必要ならアドレスも)を書きます。

   ```json
   { "web": { "remote": { "enabled": true, "username": "me" } } }
   ```

2. パスワードを設定します。二回たずね、`settings.json` ではなく `credentials.json`(モード 0600)にソルト付き scrypt ハッシュとしてだけ保存します。`--stdin` はスクリプト向けに一行を読み、`--clear` は削除します。

   ```bash
   snowpea web password
   snowpea web password --stdin
   snowpea web password --clear
   ```

3. デーモンを再起動します(`snowpea daemon stop` のあと `snowpea web`)。設定はデーモンの起動時に読まれ、動いているデーモンは再バインドしません。

すると `snowpea web` が別のマシン用のアドレス `http://<このマシンの LAN アドレス>:8787/web/` も表示し、そこを開くとサインイン画面が出ます。`snowpea web status` はリモートアクセスの有無、待ち受けアドレス、ユーザー名、パスワードの有無、サインイン中のセッション数を表示します。

| 設定 (`web.remote.…`) | 既定値 | 意味 |
|---|---|---|
| `enabled` | `false` | 二つ目のリスナーを起動します。 |
| `host` | `0.0.0.0` | 待ち受けるアドレス(`0.0.0.0` はすべてのインターフェース)。 |
| `port` | `8787` | 待ち受けるポート。 |
| `username` | `""` | サインインできる唯一のアカウント。 |
| `sessionHours` | `12` | サインインが続く時間。 |
| `allowedOrigins` | `[]` | WebSocket が追加で受け入れるページのオリジン(例: プロキシの後ろの `https://snowpea.example.com`)。 |
| `trustProxy` | `false` | 自分で運用するリバースプロキシの `X-Forwarded-Proto` / `X-Forwarded-For` を信用します。 |

ユーザー名かパスワードがないままリモートアクセスを有効にすると、デーモンはループバックだけで起動し、理由をログに書き、`snowpea web` もそれを伝えます。

セキュリティ上の注意:

- **平文の HTTP です。** パスワードも操作内容も暗号化されずに流れます。信頼できるネットワークの外では TLS(Caddy や nginx などのリバースプロキシと `trustProxy: true`)の後ろに置くか、VPN か上の ssh トンネルで接続してください。
- サインインした人はエージェントを、つまりこのマシンのシェルとファイルを操作できます。長いパスワードにしてください。
- 一つのアドレスから 5 分間に 5 回、または全体で 20 回サインインに失敗すると、その 5 分が過ぎるまでサインインできなくなります。成功も失敗もクライアントのアドレスと一緒にログに残り、パスワードは残りません。
- サインインはクッキー(`HttpOnly`、`SameSite=Strict`、HTTPS では `Secure`)です。セッションはデーモンのメモリにだけあるので、デーモンを再起動すると全員サインアウトされます。新しいパスワードは次のサインインから使われ、開いているセッションは期限切れ、サインアウト、デーモンの再起動まで続きます。
- リモートのリスナーが返すのはページ、サインイン、WebSocket だけです(`/health`、`/version`、スキーマはありません)。WebSocket は別のオリジンのページを拒否します。

## 画面

レイアウトは DeepSeek Harness の Web クライアントに倣っています。3 列で、真ん中が会話です。

| 列 | 内容 |
|---|---|
| 左 — サイドバー | **New Session**(新規セッション)、Plugins(プラグイン)、Automation tasks(自動化タスク)、More(その他の画面: スキル、スケジュール、設定…)、そして **Workspaces**(ワークスペース): プロジェクトフォルダごとに 1 グループで、その会話が並び、ピン留めしたものが先頭に来ます。行のドットは、ターンが実行中、承認待ち、または未読があることを示します。行のメニューからピン留め、名前の変更、フォーク、ID のコピー、アーカイブができます。 |
| 中央 — 会話 | 会話のタイトル、委任元またはフォーク元の親会話、そして 2 つのタブを持つヘッダー: **Chat**(チャット: メッセージ、ツールカード、入力欄)と **Trajectory**(トラジェクトリ。下記参照)。 |
| 右 — ドック | 会話の横に開くタブ: ファイル、ワークスペースのファイルツリー、プラン、委任された作業、変更、そして IDE ではターミナル。ペインは分割でき、タブはペイン間を移動できます。レイアウトはこのブラウザ内で会話ごとに保存されます。 |

サイドバーの幅は 280 px(端をドラッグして 264〜420 の間で調整)で、1024 px 未満ではレールに折りたたまれ、768 px 未満ではドロワーになります。`Ctrl/⌘ B` で切り替えます。ドックはウィンドウの 45 % で開き、指定した幅を保持し、70 % を超えず、会話が 400 px より狭くなるくらいなら閉じます。`Ctrl/⌘ J` で切り替えます。

## ドックで開くファイル

会話が触れたファイルは、新しいウィンドウではなくドックのタブで開きます。

- ファイルへの Markdown リンク(`[math.ts]` + `(math.ts)`)、相対パスまたは絶対パス、Windows パス
- 行または範囲: `#L24`、`#L24-L30`、`:24`、`:24-30`
- `` `src/app.ts` `` のようなインラインコード。ただし、そのターンが読んだか書いたファイルを指すときだけ
- 返信の下にあるファイルチップとアーティファクトカード

同じファイルをもう一度開くと、そのタブにフォーカスします。プレビューは IDE のものです: ハイライト付きコード、Markdown、画像、PDF、スプレッドシート、Office 文書、ノートブック。HTML ファイルはデフォルトで**静的**に表示されます(サニタイズ済み、スクリプトなし、厳格なコンテンツセキュリティポリシー)。**スクリプトを実行**に切り替えると、分離されたフレームで読み込まれ、フレーム自身のスクリプトは動きますが、ページ、Cookie、デーモンには触れません。

ブラウザではファイルはデーモン(`fs.*`)経由で読み、会話のフォルダの中だけが対象です: 作業ディレクトリ、ワークスペース、添付ファイル。それ以外のパスは、エージェント自身のツールが拒否するのと同じように拒否されます。

## トラジェクトリ

**Trajectory** タブは、エージェントが何をしたかを、チャットではなくステップ単位で表示します。ターンごとに 1 つのバンドがあり、その中のモデル呼び出しごとにテキスト、推論、ツール呼び出しを持つステップがあり、各ツール呼び出しには引数、結果、所要時間が表示されます。委任された作業は開始された場所に現れ、クリックすると子の会話がドックで開きます。ツール呼び出し内のファイルも上記のとおりドックで開きます。セッションのイベントログ(`session.trajectory`)から作られるので、実行中のターンでも、終わったターンでも、明日再開する会話でも同じ表示になります。

## フォーク、ピン留め、アーカイブ

終わったターンから会話を**フォーク**できます。そのターンまでの履歴を持つ新しい会話が始まり、元の会話はそのまま残ります。新しい会話のヘッダーには元がどこかが表示されます。ターンより前にファイルを戻す機能(チェックポイント)はこれまでどおり使えます。フォークは、今の流れを失わずに別の方向を試すためのものです。

**ピン留め**は会話をワークスペースの先頭に置きます。**アーカイブ**は削除せずにサイドバーから隠します(サイドバーの表示オプションでアーカイブ済みを再表示できます)。

## ブラウザでできないこと

ページはオペレーティングシステムにアクセスできないため、次のものは IDE とターミナル UI に残ります。

- ターミナル(ターミナルで開く、新規ターミナル)
- ローカルで動く git 操作、およびフォルダーで表示 / システムのアプリで開く
- ネイティブのフォルダ選択 — ワークスペースはパスを入力して追加します
- 返信の読み上げ

これらのボタンは、失敗するのではなくブラウザでは非表示になります。

## ページの配信元

Web ビルドは snowpea パッケージに同梱され、デーモンが `/web/` 配下で配信します。`index.html` は決してキャッシュされず、他のすべてのファイルは名前にコンテンツハッシュを含むので、アップグレード後にリロードすれば必ず新しいバージョンが届きます。開発では `SNOWPEA_WEB_DIST` でデーモンを別のビルドに向けられます。

```bash
# in snowpea-ide
npm run build:web
# then, with a separate home so your own daemon is not touched
SNOWPEA_WEB_DIST=$PWD/out/web snowpea --home /tmp/snowpea-dev web
```

ビルドがない場合、`snowpea web` はそう伝え、アドレスは `404` を返します。
