# snowpea web

`snowpea web`은 에이전트를 브라우저에서 엽니다. snowpea IDE와 같은 화면 — 같은 사이드바, 대화, 궤적(Trajectory), 독 — 을 로컬 데몬이 서비스하므로 따로 설치할 것이 없고 어떤 데이터도 내 컴퓨터 밖으로 나가지 않습니다.

```bash
snowpea web            # start the daemon if needed, print the address, open it
snowpea web --no-open  # print the address only
```

주소는 `http://127.0.0.1:<port>/web/?token=…` 형태입니다. 토큰은 데몬의 것(`$SNOWPEA_HOME/daemon.json`에 있는 그 토큰)이며, 페이지는 이를 해당 브라우저 탭에 보관하고 주소창에서는 지웁니다. 토큰을 가진 사람은 누구나 에이전트를 조종할 수 있으므로 주소를 채팅이나 티켓에 붙여 넣지 마세요. 이 주소는 데몬이 도는 컴퓨터에서만 열립니다.

## 다른 컴퓨터에서

가장 간단한 방법은 여전히 ssh 터널입니다. 따로 열리는 포트가 없고 연결도 암호화됩니다.

```bash
ssh -L <port>:127.0.0.1:<port> host
```

같은 네트워크의 노트북이나 휴대폰에서 바로 열려면 `snowpea web`에 주소와 포트를 주면 됩니다. 데몬이 재시작 없이 바로 두 번째 listener를 열고, 루프백 listener는 지금처럼 그대로 동작합니다.

```bash
snowpea web --host 0.0.0.0 --port 8787           # 비밀번호 없이 접속 링크로
snowpea web --host 0.0.0.0 --port 8787 --save    # 데몬을 다시 시작해도 같은 설정으로
```

비밀번호가 없으면 다른 컴퓨터는 출력된 **접속 링크** `http://<이 컴퓨터의 LAN 주소>:8787/web/?t=<토큰>`으로 엽니다. 토큰은 데몬 토큰과 다른, 이 용도만의 256비트 무작위 키이며 `credentials.json`(권한 0600)에 보관됩니다. 첫 방문에서 로그인 쿠키로 바뀌고, 페이지는 토큰이 빠진 같은 주소로 이동하므로 브라우저 기록에 남지 않습니다. 링크를 가진 사람은 이 컴퓨터를 다룰 수 있으니 비밀번호처럼 다루세요.

```bash
snowpea web token              # 링크를 다시 출력
snowpea web token --rotate     # 새 토큰: 이전 링크는 더 이상 열리지 않고 모두 로그아웃
```

로그인 화면을 쓰려면 사용자 이름과 비밀번호를 정합니다. 그러면 링크만으로는 열리지 않고 둘 다 묻습니다.

```bash
snowpea web --host 0.0.0.0 --port 8787 --user me --password-stdin   # stdin에서 한 줄
SNOWPEA_WEB_PASSWORD=… snowpea web --host 0.0.0.0 --port 8787 --user me
snowpea web --host 0.0.0.0 --port 8787 --user me --password '…'      # 동작하지만 아래 참고
snowpea web password             # 나중에 설정하거나 변경(두 번 묻습니다)
snowpea web password --clear     # 접속 링크 방식으로 돌아가기
```

명령줄의 `--password`도 동작하지만, 셸 기록과 프로세스 목록에 보인다는 경고를 출력합니다. `--password-stdin`이나 `SNOWPEA_WEB_PASSWORD`를 권장합니다. 비밀번호는 `settings.json`이 아니라 `credentials.json`에 salt를 넣은 scrypt 해시로만 저장합니다.

`snowpea web status`는 원격 접속이 켜졌는지, 방식(접속 링크 또는 비밀번호), 주소와 링크, 사용자 이름, 비밀번호 설정 여부, 로그인한 세션 수, 그리고 `settings.json`이 지금 실행 중인 것과 다른지(다음 데몬 시작 때 달라짐, `--save`로 현재 설정을 저장)를 보여 줍니다. 원격 접속 설정 화면이 있는 클라이언트도 같은 내용을 보여 줍니다(원격 로그인으로 연 페이지에서는 읽기 전용).

`settings.json`에 설정하고 데몬을 다시 시작하는 방법도 그대로 쓸 수 있습니다.

| 설정 (`web.remote.…`) | 기본값 | 의미 |
|---|---|---|
| `enabled` | `false` | 두 번째 listener를 시작합니다. |
| `host` | `0.0.0.0` | listen할 주소(`0.0.0.0`은 모든 인터페이스). |
| `port` | `8787` | listen할 포트. |
| `username` | `""` | 로그인할 수 있는 단 하나의 계정. |
| `sessionHours` | `12` | 로그인이 유지되는 시간. |
| `allowedOrigins` | `[]` | WebSocket이 추가로 받아 줄 페이지 origin(예: 프록시 뒤의 `https://snowpea.example.com`). |
| `trustProxy` | `false` | 직접 운영하는 리버스 프록시의 `X-Forwarded-Proto` / `X-Forwarded-For`를 믿습니다. 그 프록시 말고는 아무도 이 포트에 닿지 못할 때만 켜세요(루프백이나 프록시 전용 네트워크에 bind하거나 방화벽으로 막기). 포트에 직접 닿는 사람은 클라이언트 주소를 마음대로 꾸며 보낼 수 있습니다. |

비밀번호는 있는데 사용자 이름이 없으면 데몬은 루프백으로만 시작하고, 이유를 로그에 남기며, `snowpea web`도 그 이유를 알려 줍니다.

보안 참고:

- **평문 HTTP입니다.** 접속 링크, 비밀번호, 모든 작업이 암호화되지 않은 채 오갑니다. 믿을 수 있는 네트워크 밖이라면 TLS(Caddy, nginx 같은 리버스 프록시와 `trustProxy: true`) 뒤에 두거나 VPN 또는 위의 ssh 터널로 접속하세요.
- 로그인한 사람은 에이전트를, 그리고 그것을 통해 이 컴퓨터의 셸과 파일을 다룰 수 있습니다. 긴 비밀번호를 쓰고 링크는 남에게 보이지 마세요.
- 두 번째 listener로 들어온 연결은 링크든 비밀번호든 모두 **원격 로그인**입니다. 작업(대화, 승인, URL로 된 MCP 서버)에서는 사용자 본인으로 취급하지만 보안 설정에서는 아닙니다. 자비스, 보안 목록, 원격 접속 자체, 데몬, 허용 규칙(allowlist)을 바꾸거나, 외부 세션을 unrestricted로 열거나, CLI 경로를 확인할 수 없습니다. 이런 일은 그 컴퓨터에서 직접 하세요.
- 원격 로그인은 이 컴퓨터에서 원하는 프로그램을 실행시키거나, 나중에 들어올 길을 남겨 둘 수도 없습니다. 원격 로그인에서는 다음이 거부됩니다(페이지가 로컬 연결이 필요하다고 알려 줍니다).
  - 명령을 실행하는 MCP 서버(`command`, `args`, `env`, `cwd`)를 추가하거나 바꾸는 것, 그리고 서버에 대한 보안 경고를 무시하고 진행하는 것. URL만 있는 서버는 추가, 테스트, 변경할 수 있고, 로컬에서 저장해 둔 명령 서버는 테스트하거나 켜고 끌 수 있습니다.
  - 폴더, 링크, git URL에서 스킬이나 플러그인을 설치하는 것. 원격에서는 레지스트리(`registry:<이름>`)와 마켓플레이스의 플러그인(`<마켓플레이스>/<플러그인>`)만 설치됩니다.
  - 언어 서버의 명령, 오디오 명령 엔진·재생기·녹음기, 스킬 레지스트리 주소를 정하는 것.
  - 메신저의 토큰, 사용자·채널 id, 켜고 끄는 스위치, 그리고 채팅을 세션에 연결(bind)하는 것.
  - 제공자의 base URL(모든 프롬프트가 어디로 가는지 정합니다). 키와 모델은 계속 바꿀 수 있습니다.
  - `/update`, `/desktop`, `/allow`, `/setup`, `/allowlist remove`.
  - 파일 패널로 프로젝트의 제어 파일(`.snowpea`와 `.claude`의 hooks, commands, skills, agents, `.mcp.json`, `.git/hooks`, `.git/config`)을 쓰는 것.
- 원격 로그인이 만든 예약 작업은 작업 목록에 그렇게 표시되고, `snowpea web status`가 그 수를 보여 줍니다. 그런 작업은 그 로그인이 끝난 뒤에도 계속 실행되므로, 다른 사람이 페이지를 쓴 뒤에는 목록을 확인하세요.
- 한 주소에서 5분 안에 5번, 또는 전체에서 20번 로그인에 실패하면(틀린 비밀번호와 틀린 링크를 함께 셉니다) 그 5분이 끝날 때까지 로그인이 느려집니다. 이후의 시도는 먼저 기다린 뒤(1초에서 시작해 최대 30초까지 두 배씩) 확인하고, 그 주소의 시도는 한 번에 하나씩만 처리합니다. 맞는 비밀번호나 링크는 기다린 뒤에 그대로 들어가므로, 누가 일부러 실패를 반복해도 본인이 잠기지 않습니다. 틀린 시도에는 "시도가 너무 많습니다"라고 답합니다. IPv6 네트워크(/64)는 주소 하나로 셉니다. 로그인 성공과 실패는 클라이언트 주소와 함께 로그에 남고, 비밀번호와 토큰은 남지 않습니다.
- 로그인은 쿠키(`HttpOnly`, `SameSite=Strict`, HTTPS에서는 `Secure`)입니다. 세션은 데몬 메모리에만 있어서 데몬을 다시 시작하면 모두 로그아웃됩니다. 비밀번호를 바꾸거나 지우거나 토큰을 바꾸면 모든 사람이 즉시 로그아웃되고 열려 있던 페이지의 연결도 모두 닫힙니다. 그 밖의 세션은 만료되거나 로그아웃할 때까지 유지되며, 만료된 세션의 연결도 함께 닫힙니다.
- 세션이 끝난 페이지(만료, 비밀번호 변경, 다른 곳에서 로그아웃)는 로그인 화면으로 돌아갑니다.
- 원격 listener는 페이지, 로그인, WebSocket만 제공합니다(`/health`, `/version`, 스키마 없음). WebSocket은 다른 origin의 페이지를 거부합니다.

## 화면 구성

레이아웃은 DeepSeek Harness 웹 클라이언트를 따릅니다. 세 개의 열이고 가운데가 대화입니다.

| 열 | 들어 있는 것 |
|---|---|
| 왼쪽 — 사이드바 | **새 세션**, 플러그인, 자동화 작업, 더보기(그 밖의 화면: 스킬, 스케줄, 설정…), 그리고 **작업 공간**: 프로젝트 폴더마다 하나의 그룹이 있고 그 안에 대화가 들어 있으며, 고정한 대화가 먼저 나옵니다. 행의 점은 턴이 실행 중이거나, 승인을 기다리거나, 읽지 않은 내용이 있다는 뜻입니다. 행 메뉴에서 고정, 이름 변경, 포크, ID 복사, 보관을 할 수 있습니다. |
| 가운데 — 대화 | 대화 제목, 이 대화가 위임되었거나 포크되어 나온 부모 대화들, 그리고 두 개의 탭이 있는 헤더: **대화**(메시지, 툴 카드, 입력창)와 **궤적(Trajectory)**(아래 참고). |
| 오른쪽 — 독 | 대화 옆에 열리는 탭들: 파일, 작업 공간 파일 트리, 계획, 위임된 작업, 변경 사항, 그리고 IDE에서는 터미널. 창을 나눌 수 있고 탭은 창 사이를 옮길 수 있습니다. 레이아웃은 이 브라우저에서 대화별로 저장됩니다. |

사이드바 너비는 280 px(가장자리를 끌어 264~420 사이로 조절)이고, 1024 px 미만에서는 레일로 접히며, 768 px 미만에서는 서랍이 됩니다. `Ctrl/⌘ B`로 토글합니다. 독은 창의 45 %로 열리고, 지정한 너비를 기억하며, 70 %를 넘지 않고, 대화가 400 px보다 좁아지게 두느니 닫힙니다. `Ctrl/⌘ J`로 토글합니다.

독의 빈 패널에는 **시작** 탭이 나오며, 워크스페이스 파일, 변경 사항, 계획 카드가 있습니다(터미널 카드는 IDE 전용). 상태 표시줄은 연결 여부를 보여 주며, 열린 탭이 있으면 데몬이 유휴 상태라는 이유로 종료되지 않습니다.

## 독에서 열리는 파일

대화가 언급한 파일은 새 창이 아니라 독의 탭으로 열립니다.

- 파일로 가는 마크다운 링크(`[math.ts]` + `(math.ts)`), 상대 또는 절대 경로, Windows 경로
- 줄 또는 범위: `#L24`, `#L24-L30`, `:24`, `:24-30`
- `` `src/app.ts` ``와 같은 인라인 코드 — 단, 그 턴이 읽거나 쓴 파일을 가리킬 때만
- 그 턴이 읽거나 쓴 파일을 가리키는 답변 속 파일명(예: `notes.md`). 그 밖의 파일명은 일반 텍스트로 남고, 일반 텍스트는 명시적인 http(s), mailto: 또는 www. 주소일 때만 링크가 됩니다.
- 답변 아래의 파일 칩과 아티팩트 카드

같은 파일을 다시 열면 그 탭으로 이동합니다. 미리보기는 IDE의 것입니다: 구문 강조된 코드, 마크다운, 이미지, PDF, 스프레드시트, 오피스 문서, 노트북. HTML 파일은 기본적으로 **정적**으로 표시됩니다(정제됨, 스크립트 없음, 엄격한 콘텐츠 보안 정책). **스크립트 실행**으로 바꾸면 격리된 프레임에서 불러오며, 그 프레임은 자체 스크립트를 실행할 수 있지만 페이지, 쿠키, 데몬에는 접근할 수 없습니다.

브라우저에서 파일은 데몬(`fs.*`)을 통해 읽으며, 대화의 폴더 안에서만 읽습니다: 작업 디렉터리, 작업 공간, 첨부 파일. 그 밖의 경로는 에이전트의 도구가 거부하는 것과 똑같이 거부됩니다.

## 궤적(Trajectory)

**궤적(Trajectory)** 탭은 에이전트가 한 일을 채팅이 아니라 단계별로 보여 줍니다. 턴마다 하나의 밴드가 있고, 그 안의 모델 호출마다 텍스트, 추론, 툴 호출을 담은 단계가 있으며, 각 툴 호출에는 인자, 결과, 걸린 시간이 표시됩니다. 위임된 작업은 시작된 자리에 나타나고, 클릭하면 자식 대화가 독에서 열립니다. 툴 호출 안의 파일도 위와 같이 독에서 열립니다. 세션의 이벤트 로그(`session.trajectory`)로 만들어지므로 실행 중인 턴이든, 끝난 턴이든, 내일 다시 이어가는 대화든 똑같이 보입니다.

## 포크, 고정, 보관

끝난 턴에서 대화를 **포크**할 수 있습니다. 그 턴까지의 기록을 가진 새 대화가 시작되고 원래 대화는 그대로 남습니다. 새 대화의 헤더에 어디서 왔는지 표시됩니다. 턴 이전으로 파일을 되돌리는 것(체크포인트)은 전과 같이 동작합니다. 포크는 지금 것을 잃지 않고 다른 방향을 시도하기 위한 기능입니다.

**고정**은 대화를 작업 공간의 맨 위에 둡니다. **보관**은 삭제하지 않고 사이드바에서 숨깁니다(사이드바의 보기 옵션에서 보관된 대화를 다시 볼 수 있습니다).

## 브라우저가 할 수 없는 것

페이지는 운영 체제에 접근할 수 없으므로 다음은 IDE와 터미널 UI에서만 할 수 있습니다.

- 터미널(터미널에서 열기, 새 터미널)
- 로컬에서 실행되는 git 동작, 그리고 폴더에서 보기 / 시스템 앱으로 열기
- 터미널, 파일, 워크트리 화면, 연결 관리자와 앱 자동 업데이트(이 주소들은 대화로 돌아갑니다)
- 기본 폴더 선택기 — 작업 공간은 경로를 입력해 추가하세요

이 기능의 버튼은 실패하는 대신 브라우저에서 숨겨집니다.

## 페이지는 어디서 오는가

웹 빌드는 snowpea 패키지에 들어 있고 데몬이 `/web/` 아래에서 서비스합니다. `index.html`은 캐시되지 않고 다른 모든 파일은 이름에 콘텐츠 해시가 있으므로, 업그레이드 후 새로고침하면 항상 새 버전을 받습니다. 개발할 때는 `SNOWPEA_WEB_DIST`로 데몬이 다른 빌드를 가리키게 할 수 있습니다.

```bash
# in snowpea-ide
npm run build:web
# then, with a separate home so your own daemon is not touched
SNOWPEA_WEB_DIST=$PWD/out/web snowpea --home /tmp/snowpea-dev web
```

빌드가 없으면 `snowpea web`이 그렇게 알려 주고 주소는 `404`로 응답합니다.
