# 자비스 모드 (베타)

자비스 모드는 세션들을 한곳에서 지켜보는 감독 대화입니다. 자비스 세션 하나가 사용자가 공유한 세션을 보고, 무엇을 하고 있는지 보고하고, 사용자가 맡긴 일은 스스로 결정하고, 나머지는 사용자에게 가져옵니다. 세션을 여러 개 동시에 돌릴 때, 또는 화면 앞에 없는 동안에도 일을 계속 진행시키고 싶을 때 쓰세요.

이 기능은 베타입니다. 요청을 잘못 판단할 수 있고, 아직 자비스가 결정할 수 없는 세션 종류도 있습니다. 무엇이든 맡기기 전에 [보안 참고 사항과 알려진 제한](#보안-참고-사항과-알려진-제한)을 읽으세요.

다른 언어: [English](../en/jarvis.md) · [전체 목록](../README.md)

관련 문서: [외부 세션 (베타)](external-sessions.md) · [보안 목록](security.md) · [에이전트와 위임](agents.md) · [게이트웨이](gateway.md) · [snowpea 웹](web.md) · [음성](voice.md)

## 자비스 모드란

자비스가 없으면 모든 세션이 사용자를 기다립니다. 명령마다 승인하고, 질문마다 답하고, 세션이 중간에 멈추면 "계속"이라고 직접 입력해야 합니다.

자비스 모드를 켜면 이렇게 바뀝니다.

- 자비스가 사용자가 공유한 세션의 상태를 읽고, 그 상태를 계속 파악해 둡니다. 새 세션은 직접 켜기 전에는 공유되지 않습니다. [자비스가 보는 세션](#자비스가-보는-세션)을 보세요.
- 사용자가 맡긴 범위의 승인과 질문은 자비스가 답하고, 그 결정을 기록으로 남깁니다.
- 세션을 완전히 맡겨 둔 경우에는 자비스가 세션을 계속 진행시킵니다.
- 끝난 일, 실패한 일, 사용자의 결정이 필요한 일을 하나의 목록으로 알려 줍니다.
- 어느 화면에서든 자비스에게 특정 세션에 대해 묻거나 보고서를 요청할 수 있습니다.

자비스 모드는 **기본으로 꺼져 있습니다**. 직접 켜기 전에는 아무것도 바뀌지 않습니다.

### 켜는 방법

| 어디서 | 방법 |
|---|---|
| 데스크톱 앱 또는 snowpea 웹 | 사이드바의 **자비스**를 열고 **자비스 켜기**를 누릅니다. **설정 → 자비스·에이전트**를 열어 **자비스 켜기**를 켜도 됩니다. |
| 터미널 UI | `/jarvis on`을 입력합니다. `/jarvis`만 입력하면 자비스 화면이 열립니다. |
| 터미널(UI 밖) | `snowpea jarvis`를 실행합니다. 자비스 화면이 열린 터미널 UI가 뜹니다. |
| 메신저 | 사용자에게 연결된 채팅에서 `/jarvis on`을 보냅니다. 이 채팅에 연결된 사람만 켤 수 있습니다. [메신저](#메신저)를 보세요. |

끄려면 자비스 화면의 **자비스 끄기**를 누르거나, 터미널 UI에서 `/jarvis off`를, 연결된 메신저 채팅에서 `/jarvis off`를 보냅니다. 자비스 모드를 끄면 모든 승인과 질문이 다시 사용자에게 옵니다.

자비스는 데몬 하나당 세션 하나로 돌아갑니다. `jarvis.model`에 지정한 모델을 씁니다. 비워 두면 기본 모델을 씁니다.

자비스의 작업 폴더는 기본으로 `~/Snowpea/Jarvis`입니다(`jarvis.folder`). 보고서와 할 일 목록은 이 폴더에 저장됩니다. 이 폴더는 snowpea의 홈 폴더나 인증 정보 폴더 안에 있으면 안 됩니다. 설정이 그런 경로를 거부하고, 자비스도 그런 경로에서는 시작하지 않습니다.

## 자비스가 보는 세션

자비스는 사용자가 공유한 세션만 봅니다. 세션마다 자비스 스위치가 있고, 새 세션은 **공유하지 않은 상태**로 시작합니다.

- **공유(켬):** 세션이 자비스 개요에 나옵니다. 자비스가 세션을 읽고 지시를 보낼 수 있고, 맡긴 범위 안에서 승인과 질문을 결정합니다. 그 세션에 대한 자비스 알림이 옵니다.
- **공유 안 함(끔, 기본값):** 자비스에게 그 세션은 없는 세션입니다. 개요에 나오지 않고, 자비스의 도구로 읽거나 지시할 수 없고, 승인과 질문은 자비스 모드를 껐을 때와 똑같이 사용자에게 옵니다. 그 세션에서는 아무것도 자동 허용되지 않습니다. 그 세션에 대한 자비스 알림도 없습니다.

바꾸는 방법:

| 어디서 | 방법 |
|---|---|
| 터미널 UI, 세션 안에서 | `/jarvis share on` 또는 `/jarvis share off`. `/jarvis share`만 입력하면 지금 상태를 보여 줍니다. 켜져 있는 동안 상태 줄에 **Jarvis: shared**가 보입니다. |
| 터미널 UI, 자비스 화면 | 공유하지 않은 세션이 몇 개인지 보여 줍니다. `/jarvis share on <세션 id>`로 하나를 공유합니다. |
| 데스크톱 앱 또는 snowpea 웹 | 세션 머리말이나 자비스 화면의 세션 목록에 있는 자비스 스위치. |

원격 웹 로그인으로도 바꿀 수 있습니다. 자비스, 세션 안의 도구, 메신저나 브라우저 연결은 바꿀 수 없습니다.

저절로 켜지는 경우:

- **세션 위임.** 세션 하나를 맡기는 위임("맡기기")을 확인하면, 그 확인으로 세션도 공유됩니다. 프로젝트 위임이나 "전부 맡기기"는 세션을 공유하지 **않습니다**. 공유한 세션에만 적용됩니다.
- **자비스가 만든 세션.** 자비스가 사용자를 위해 시작한 세션(snowpea, 외부 CLI, 브라우저)은 공유된 상태로 시작하고, 기록에도 남습니다.
- **자식 세션과 포크**는 원래 세션의 스위치를 따릅니다.

세션을 끄더라도 위임은 지워지지 않습니다. 꺼져 있는 동안 효력이 없을 뿐입니다. 그 세션에서 자비스를 기다리던 요청은 곧바로 사용자에게 옵니다. 다시 켜면 기다리던 요청은 방금 들어온 것처럼 다시 분류됩니다.

그 밖의 규칙:

- 자비스에게 숨긴 프로젝트(`jarvis.expose` 끔)의 세션은 스위치와 상관없이 모두 숨겨집니다. 스위치는 잠긴 상태로 보입니다.
- 브라우저 세션은 `jarvis.exposeBrowser`가 켜져 있을 때만 공유할 수 있습니다.
- `jarvis.sessions.default`(`off` 또는 `on`)가 새 세션의 시작 상태를 정합니다. 이 컴퓨터에서 사용자만 바꿀 수 있습니다.
- 끈 세션에 대한 기록은 사용자의 기록에는 남지만, 자비스는 더 이상 읽지 않습니다.

**업그레이드 후:** 기존 세션은 공유하지 않은 상태가 됩니다. 단, 세션 하나씩 자비스에게 맡겨 두었던 세션은 공유된 상태로 남습니다. 자비스 화면에 한 번 안내가 나옵니다.

## 자비스가 할 수 있는 일과 할 수 없는 일

| 자비스가 할 수 있는 일 | 자비스가 할 수 없는 일 |
|---|---|
| 노출된 프로젝트에서 사용자가 공유한 세션의 상태, 요약, 최근 기록을 읽음 | 공유하지 않은 세션이나 자비스에게 숨긴 프로젝트를 읽음 |
| 전역 메모리와 노출된 프로젝트의 메모리를 읽음 | 자기 메모리 말고 다른 메모리에 씀 |
| 자기 작업 폴더 안에서만 파일을 씀 | 사용자의 프로젝트 파일을 직접 씀. 변경은 작업 세션을 통해서만 합니다. |
| snowpea가 실행하는 세션, 그리고 snowpea가 통제하는 외부 세션에 지시를 보냄 | snowpea가 통제하지 않는 세션(예: 제한 없음 모드의 외부 세션)에 지시함 |
| 자기에게 배정된 승인과 질문에 답함 | 자기 승인에 답하거나 자기 권한을 넓힘 |
| 세션의 권한 모드를 낮춤 | 세션의 권한 모드를 높임. 사용자만 높일 수 있습니다. |
| 짧은 검색어로 웹을 검색함(200자 이하) | URL을 열어 봄. URL을 가져오는 도구가 없습니다. |
| 프로젝트 파일과 자기 작업 폴더의 파일을 읽음 | snowpea 홈 폴더 안의 것(토큰, 설정, 인증 정보, 기록)을 읽음 |
| 권한 위임을 제안함 | 스스로 위임을 만들거나 넓힘. 위임은 사용자만 확정할 수 있습니다. |

가장 중요한 세 가지 규칙입니다.

- **자비스는 작업 세션에 지시하는 방식으로만 프로젝트를 바꿉니다.** 프로젝트 파일을 직접 고치지 않습니다.
- **자비스가 읽은 내용으로는 권한이 늘지 않습니다.** 웹 페이지, 메일, 로그, 외부 세션의 출력은 위임을 바꿀 수 없습니다. 자비스가 답한 질문은 "사용자가 아니라 자비스가 답함"이라는 표시와 함께 작업 세션에 전달됩니다.
- **권한 모드를 높이는 것은 사람만 합니다.** 세션의 모드는 자비스나 에이전트가 낮출 수 있지만(예: 자동에서 수락으로), 높이려면 사용자가 직접 답해야 합니다. 다른 누가 답하려 하면 그 질문이나 명령은 거부되고, 어떤 위임으로도 이 규칙은 바뀌지 않습니다. [모드](modes.md)를 보세요.

## 위임

위임은 자비스가 사용자에게 묻지 않고 스스로 결정해도 되는 범위를 정합니다. 자비스는 사용자가 준 위임의 범위를 넘어서지 않습니다.

### 수준

| 수준 | 자비스가 결정하는 것 |
|---|---|
| **단계별** (기본) | 안전한 승인과 읽기만 하는 승인, 방법을 묻는 질문. 그보다 위험한 것은 모두 사용자에게 옵니다. |
| **다 맡김** | 단계별의 모든 것에 더해, 위험한 승인, 멈춤, 질문, 끝나지 않은 턴까지 결정합니다. 세션을 계속 진행시킵니다. |

위임이 없는 상태는 단계별입니다. 다 맡김은 기본값이 될 수 없습니다. 특정 범위에 위임으로 주는 것입니다.

### 범위

위임은 다음 범위 중 하나에 적용됩니다.

- **세션**: 세션 하나에만 적용됩니다. 세션이 끝나거나 회수할 때까지 유효합니다.
- **프로젝트**: 프로젝트 하나의 모든 세션에 적용됩니다. 만료를 정하지 않으면 기본 24시간입니다(`jarvis.delegation.projectTtlHours`).
- **전체**: 전역 위임입니다. 회수할 때까지 노출된 모든 프로젝트에 적용됩니다.

### 세션이나 프로젝트를 맡기는 방법

1. 원하는 것을 자비스에게 대화로 말합니다. 예: "이 세션 단계별로 맡아 줘." 또는 "이 프로젝트 전체를 다 맡겨 줘."
2. 자비스가 확인 카드를 띄웁니다. 카드에는 범위, 수준, 사용자가 넘기기로 한 위험 항목(아래 참고), 만료, 자비스가 그렇게 제안한 이유가 나옵니다.
3. **확인**을 한 번 누릅니다. 사용자만 누를 수 있습니다. 자비스가 읽은 어떤 글로도 위임은 확정되지 않습니다. 메신저에서는 연결된 채팅에서 한 번 답하는 것으로 확정합니다.

원격 웹 로그인으로는 위험 항목을 위임에 넘길 수 없습니다([다른 컴퓨터에서 자비스 쓰기](#다른-컴퓨터에서-자비스-쓰기) 참고). 그 작업은 그 컴퓨터에서 직접 하세요. 기본으로는 grant 자체를 줄 수 없습니다. 이 컴퓨터에서 **원격 웹 로그인에서 위임 허용**을 켜 두면, 원격 비밀번호를 다시 입력하고 세션 하나나 프로젝트 하나를 위험 항목 없이 최대 24시간 맡길 수 있습니다([snowpea 웹](web.md#원격-로그인에서-위임하기)).

변경하지 않으려면 **거절**을 누릅니다. 자비스는 원래 가진 권한을 그대로 유지합니다.

자비스는 위임을 제안할 수 있지만 스스로 만들 수는 없습니다. 자비스가 제안한 위임은 목록에 **자비스가 제안함**으로 표시되고, 사용자가 확정하기 전에는 효력이 없습니다.

### "전부 맡기기"

전역 다 맡김 위임이 "전부 맡기기"입니다. 다른 위임과 같은 방법으로, 확인 한 번으로 줍니다. 기본 설정은 다 맡김이 될 수 없습니다(`jarvis.delegation.default`는 `staged`만 받습니다). 이전 베타가 저장해 둔 다 맡김 값은 단계별로 불러오고, snowpea가 올바른 방법으로 다시 주라는 안내를 한 번 띄웁니다.

### 위험 항목

위험 항목은 세 종류입니다. 다 맡김 상태에서도 따로 맡기지 않은 항목은 자비스가 사용자에게 묻습니다.

| 항목 | 해당하는 것 |
|---|---|
| 배포·릴리스·푸시 | 배포, 릴리스, 푸시(같은 종류의 공개와 병합 포함) |
| 프로젝트 밖, 삭제 | 프로젝트 폴더 밖의 작업, 삭제, 강제 초기화 |
| 비밀정보와 외부 전송 | 토큰, 비밀번호 같은 비밀정보, 데이터를 밖으로 보내기(업로드, 메일, 공유) |

위임 카드에는 이 세 항목이 **추가로 맡길 항목** 체크박스로 나옵니다. 세 항목 모두 기본으로 꺼져 있습니다.

### 항상 사용자에게 가는 것

다음은 어떤 위임으로도 바뀌지 않습니다. 나머지를 모두 허용하더라도 자비스가 결정하지 않습니다.

- snowpea 홈 폴더 안의 것: 토큰, 설정, 인증 정보, 세션과 메모리 기록, 데이터베이스 파일.
- 에이전트 CLI 자체의 권한 파일. 예를 들어 `.claude/`나 `.codex/` 아래의 설정.
- snowpea 자체 설정의 변경.
- 세션의 권한 모드를 높이는 일.
- 위험 항목을 언급하거나 비밀정보를 묻는 질문.
- 차단 명령 목록과 대조할 수 없는 줄. [보안 목록](#보안-목록)을 보세요.
- 브라우저 세션의 결제, 정기 구매(만들기·바꾸기·다시 시작), 사용자 자신의 탭 사용. 공유한 브라우저 세션의 나머지 승인은 위임을 따릅니다(1.56.0).
- 자비스와 공유하지 않은 세션의 모든 것.

### 위임 보기와 회수

**설정 → 위임**을 엽니다. 각 위임의 범위, 수준, 넘긴 위험 항목, 누가 주었는지, 만료 시각이 보입니다. 만료된 위임은 **만료된 항목 보기**를 켜야 나옵니다.

위임을 끝내려면 **회수**를 누르고 확인합니다. 자비스는 그 범위에서 기본 수준으로 돌아갑니다. 이미 내린 결정은 그대로 남습니다.

위임을 만들고 바꾼 모든 기록은 자비스의 원장에 남습니다.

## 자동 허용, 자비스가 결정함, 사용자에게 옴

| 요청 | 단계별 | 다 맡김 |
|---|---|---|
| 안전한 승인(권한 규칙이 안전하다고 분류한 일상적이고 위험이 낮은 작업) | 자동 허용. 기록됨. 모델을 부르지 않음. | 같음 |
| 읽기만 하는 승인(읽기만 하지만 안전 목록에는 없는 명령. 카드에 "읽기만 함"이 표시됨) | 자비스가 결정. 한 번 허용하거나 사용자에게 넘김 | 자비스가 결정 |
| 그 밖의 위험한 승인 | 사용자에게 옴 | 자비스가 결정 |
| 방법을 묻는 질문 | 자비스가 답함. 작업 세션에는 자비스가 답했다고 전달됨. | 자비스가 답함 |
| 그 밖의 질문 | 사용자에게 옴 | 자비스가 결정. 위험 항목이나 비밀정보와 관련되면 사용자에게 옴. |
| 멈춘 세션이나 끝나지 않은 세션 | 사용자에게 옴 | 자비스가 계속 진행시킴 |
| 위험 항목(배포, 프로젝트 밖이나 삭제, 비밀정보와 외부 전송) | 사용자에게 옴 | 따로 맡기지 않았다면 사용자에게 옴 |
| 항상 사용자에게 가는 것(snowpea 기록과 설정, CLI 자체 권한 파일, 모드 높이기) | 사용자에게 옴 | 사용자에게 옴 |
| snowpea가 읽을 수 없는 복합 명령 | 위험 항목으로 취급 | 위험 항목으로 취급 |
| 차단된 명령 | 누구에게도 묻지 않음. 실행되지 않음. | 같음 |

**안전함과 읽기만 함의 차이.** 안전한 명령은 정해진 짧은 목록입니다. 모든 대상이 프로젝트 안의 평범한 경로인 `ls`, `cat`, `head`, `wc`, 평범한 `grep` 같은 것입니다. 읽기만 하는 명령은 읽기만 하지만 더 멀리 닿거나 무언가를 실행할 수 있는 명령입니다. 프로젝트 최상위에서 실행하는 읽기 전용 `git` 명령(`git status`, `git diff`, `git log` 등), `rg`, `jq`, `grep -r`·`ls -R`·`find -L` 같은 재귀 옵션, 와일드카드, 외부 CLI가 보낸 셸 명령이 여기에 속합니다. 자비스는 명령이 분명히 읽기만 하고 모든 경로가 프로젝트 안에 머물 때만 한 번 허용합니다. 그렇지 않으면 사용자에게 넘깁니다.

어떤 요청이 표의 어느 줄에도 맞지 않으면 자비스는 더 신중한 쪽을 골라 사용자에게 보냅니다.

## 직접 끼어들기

자비스가 관리하는 세션에서 직접 작업할 수 있습니다.

- **입력하면 자비스가 그 세션에서 멈춥니다.** 자비스가 관리하는 세션에 입력하면, 그 세션에서는 자비스가 더 결정하지 않습니다. 세션 배너에 **직접 입력 중이라 멈춤**이 표시됩니다.
- **입력이 없으면 자동으로 돌아옵니다.** 사용자의 입력이 `jarvis.quietMinutes`(기본 10분) 동안 없으면 자비스가 돌아옵니다. 배너에 남은 시간이 표시됩니다.
- **지금 다시 맡김.** 세션 배너의 **지금 다시 맡김**을 누르거나, 터미널 UI에서 `/jarvis handback`, 메신저에서 `/jarvis handback <이름>`을 입력합니다. 자비스가 바로 돌아옵니다.
- **직접 맡기.** 배너의 **직접 맡기**를 누르거나 터미널 UI에서 `/jarvis takeover`를 입력합니다. 다시 맡길 때까지 사용자가 세션을 가집니다. 자비스는 저절로 돌아오지 않습니다. 터미널 UI에서 `/jarvis takeover <분>`은 그 분 동안만 세션을 가지고, `/jarvis takeover <번호> <분>`은 목록의 번호로 세션을 골라 그렇게 합니다.

이 규칙에서 입력으로 치는 것은 세션에 직접 입력한 내용뿐입니다. 다른 세션에 입력해도 이 세션의 자비스는 멈추지 않습니다.

## 알림

자비스는 묻지 않은 것을 모두 알리지 않습니다. 중요한 것만 알립니다. 종류마다 끌 수 있습니다.

| 알림 | 설정 | 기본값 |
|---|---|---|
| 세션이 끝남 | `jarvis.proactive.finished` | 켬 |
| 세션이 실패하거나 오류로 멈춤 | `jarvis.proactive.error` | 켬 |
| 사용자의 결정이 필요함 | `jarvis.proactive.needsYou` | 켬 |
| 자비스가 대신 결정함 | `jarvis.proactive.decided` | 켬 |

알림이 나타나는 곳입니다.

| 장소 | 받는 알림 | 설정 |
|---|---|---|
| 앱과 터미널 UI(표시와 목록) | 모든 알림 | `jarvis.notify.inApp`(켬) |
| 운영체제(데스크톱 알림) | 중요도 보통 이상 | `jarvis.notify.os`(켬) |
| 메신저(본인의 개인 채팅) | 중요도 높음과 긴급만 | `jarvis.notify.messenger`(켬) |

알림은 닫을 때까지 목록에 남습니다.

- 앱에서는 **닫기**를 누릅니다. **사용자를 기다림** 패널에서는 **N건 모두 닫기**(N은 남은 건수)를 누릅니다.
- 터미널 UI에서는 `/jarvis waiting`으로 목록을 보고, `/jarvis dismiss <번호>` 또는 `/jarvis dismiss all`을 입력합니다.
- 메신저에서는 연결된 사람의 개인 채팅으로만 알림이 옵니다.

## 보안 목록

차단 명령과 보호 폴더는 자비스에게도 사용자와 똑같이 적용됩니다. 자비스, 작업자, 위임이 결정하기 전에 먼저 확인합니다. snowpea 가 읽는 줄의 차단된 명령은 자비스에게 가지 않고, 실행되지 않으며, 권한으로 허용할 수도 없습니다(스크립트나 프로그램이 실행된 뒤 하는 일은 읽지 않습니다. 아래 한계를 보세요). 자비스 기록(ledger)에 차단이 남습니다. 목록과 대조할 수 없는 줄(변수에 든 프로그램, `eval`, 셸로 파이프한 스크립트)은 자비스가 아니라 항상 사용자에게 갑니다. 카드에 "차단 목록과 대조할 수 없습니다"라고 표시됩니다. unrestricted 로 실행 중이거나 자기 터미널에서 권한 요청에 답하는 외부 세션은 개요에 표시되며, 목록이 그 안까지는 닿지 않습니다. 프리셋, 패턴 문법, 한계는 [보안 목록](security.md)을 보세요.

## 프로젝트

자비스는 사용자가 노출한 프로젝트를 감독합니다.

- **노출은 프로젝트마다 정합니다.** 모든 프로젝트는 기본으로 노출됩니다. 프로젝트 설정의 **자비스에게 공개**를 끄면 그 프로젝트는 자비스에게 완전히 숨겨집니다. 자비스는 그 프로젝트의 세션, 기록, 메모리를 볼 수 없습니다. 숨긴 프로젝트 수는 설정에 "자비스에게 숨겨져 있는 프로젝트 N개"로 표시됩니다. 이 스위치는 프로젝트 자체의 `.snowpea/settings.json`에 `jarvis.expose`로 저장됩니다. 그 파일을 읽을 수 없으면 snowpea는 그 프로젝트를 숨긴 것으로 취급합니다.
- **숨긴 프로젝트 아래의 프로젝트도 숨겨집니다.** 등록된 프로젝트 위의 폴더가 숨겨지면 그 프로젝트도 숨겨집니다.
- **브라우저 세션**(snowpea 브라우저가 돌리는 세션)은 `jarvis.exposeBrowser`를 따릅니다. 기본은 켬입니다. 끄면 그 세션들은 자비스에게 숨겨지고(1.56.0부터는 상태도 목록에 나오지 않습니다) 공유할 수 없습니다. 켜져 있으면, 사용자가 공유한 브라우저 세션은 다른 세션처럼 위임을 따릅니다.
- **이름.** 자비스는 snowpea가 프로젝트에 붙인 이름과, 사용자가 붙인 별칭으로 프로젝트를 부릅니다. 대화에서도 같은 이름을 쓰세요. 프로젝트 이름이나 별칭이 "웹사이트"라면 "웹사이트 프로젝트"라고 말하면 됩니다.
- **이름 바꾸기와 별칭.** 프로젝트의 표시 이름과 별칭은 모든 프로젝트 밖인 snowpea 홈 폴더에 저장됩니다. 프로젝트 안에서 일하는 세션이 이름을 바꿀 수 없게 하려는 것입니다. 이름과 별칭은 클라이언트가 `jarvis.project.rename`, `jarvis.project.alias` 호출로 바꿉니다([프로토콜 문서](protocol.md) 참고). 자비스에게는 이를 설정하는 도구가 없어서, 자비스에게 말로 시켜서 바꿀 수는 없습니다.

## 메신저

자비스 모드를 켜면 연결된 메신저 채팅은 일반 세션이 아니라 자비스와 대화합니다.

- **연결된 사람만.** 자비스는 채팅에 연결된 사람하고만 대화합니다. 그룹 채팅의 다른 사람에게는 자비스가 이 채팅에서는 소유자와만 대화한다는 짧은 답이 나갑니다. 이 답은 10분에 한 번 넘게 나가지 않습니다. 다른 사람이 쓴 글은 자비스에게 전달되지 않습니다.
- **자비스가 먼저 보내는 것은 개인 채팅으로만.** 알림, 브리핑, 위임 확인 요청, 전달된 요청은 연결된 사람의 개인 채팅으로만 가고, 그룹 채팅으로는 가지 않습니다. snowpea가 그 사람의 개인 채팅을 모르면 아무것도 보내지 않고, 앱에 "메신저: 개인 채팅 없음"이라는 알림을 띄웁니다. 봇에게 개인 메시지를 한 번 보내면 snowpea가 그 채팅을 알게 됩니다. 이 알림은 한 시간에 한 번 넘게 반복되지 않습니다.
- **숨긴 프로젝트는 숨긴 채로.** 자비스에게 숨긴 프로젝트의 요청은 메신저로도 전달되지 않습니다.
- **전달된 메시지.** 누군가 전달한 메시지는 인용된 신뢰할 수 없는 글로 자비스에게 전달됩니다. 이 메시지는 위임을 확정할 수 없습니다.
- **라우팅.** `jarvis.messenger.route`(켬)가 켜져 있으면 자비스 모드가 켜진 동안 채팅이 자비스로 갑니다. 자비스 모드를 끄면 채팅은 원래 연결된 세션으로 돌아갑니다.
- **다른 슬래시 명령은 잠깁니다.** 자비스 모드가 채팅을 자비스로 보내는 동안에는 snowpea의 다른 `/` 명령이 이 채팅에서 실행되지 않습니다. 자비스 자신의 세션에 작용하게 되기 때문입니다. 아래의 `/jarvis` 명령을 쓰세요.

메신저 채팅에서 쓰는 명령입니다.

| 메시지 | 하는 일 | 누가 |
|---|---|---|
| `/jarvis` 또는 `/jarvis status` | 세션 목록, 실행 중인 세션 수, 사용자를 기다리는 세션 수를 보여 줌 | 연결된 사람 |
| `/jarvis on` 또는 `/jarvis off` | 자비스 모드를 켜거나 끔 | 연결된 사람 |
| `/jarvis takeover <이름>` | 이름이 가리키는 세션을 사용자가 맡음. 다시 맡길 때까지 자비스는 그 세션에서 결정하지 않음. | 연결된 사람 |
| `/jarvis handback <이름>` | 이름이 가리키는 세션을 자비스에게 다시 맡김 | 연결된 사람 |
| `/jarvis help` | 명령 목록을 보여 줌 | 누구나 |

짧은 형태도 됩니다. `enable`, `disable`, `take`, `back`, `return`을 쓸 수 있고, 한국어로 `켜기`, `끄기`, `인수`, `반환`, `상태`도 됩니다. 이름이 세션 여러 개와 맞으면 snowpea가 목록을 보여 주고 더 정확히 입력하라고 답합니다.

메신저에서 위임을 확정하는 것은 기본으로 허용됩니다(`jarvis.messenger.allowGrants`, 켬). 그래도 확정하려면 같은 채팅에서 한 번 눌러야 하고, 그 한 번은 사용자만 할 수 있습니다. 확인 창에는 첫 메시지 전체가 나옵니다. 그 메시지가 3,000자를 넘으면 일부만 보여 주는 대신 확정을 거부합니다.

메신저에서 위임을 확정하지 못하게 하려면 `jarvis.messenger.allowGrants`를 `false`로 설정합니다. 그러면 위임은 앱이나 터미널 UI에서만 줄 수 있습니다.

채팅을 snowpea에 연결하는 방법은 [게이트웨이](gateway.md)를 보세요.

## 다른 컴퓨터에서 자비스 쓰기

다른 컴퓨터에서 snowpea 웹을 열어([snowpea 웹](web.md#다른-컴퓨터에서)) 거기서 자비스와 대화할 수 있습니다. 요약하면 이렇습니다.

- `snowpea web --host <주소> --port <번호>`는 데몬을 다시 시작하지 않고 바로 원격 접속을 엽니다. `--save`를 붙이면 데몬이 시작될 때마다 유지됩니다.
- 비밀번호가 없으면 **접속 링크** `http://<주소>:<번호>/web/?t=<토큰>`이 출력됩니다. 링크 속 토큰은 데몬 토큰이 아니라 웹 접속용으로 따로 만든 토큰입니다. 처음 열면 로그인 쿠키로 바꾸고 주소에서 토큰을 지웁니다.
- 로그인 화면을 쓰려면 사용자 이름과 비밀번호를 정합니다. `--user <이름>`과 함께 `--password-stdin`, `SNOWPEA_WEB_PASSWORD` 환경 변수, 또는 `--password`(셸 기록에 남음)를 씁니다. 나중에는 `snowpea web password`로 정하거나 바꿉니다.

원격 접속으로 들어온 연결은 링크로 들어왔든 비밀번호로 들어왔든 모두 **원격 로그인**입니다. 원격 로그인은 사용자 본인입니다. 링크나 비밀번호를 가진 사람은 누구나 사용자 본인으로 snowpea를 쓸 수 있고, 이 컴퓨터에서 명령을 실행할 수 있습니다. 제한된 계정이 아닙니다.

그래도 몇 가지는 이 컴퓨터에 남겨 둡니다. 실수나 잠깐 빌려 쓴 세션이 클릭 한 번으로 바꾸지 못하게 하려는 것입니다. 원격 로그인은 snowpea의 화면으로 다음을 할 수 없습니다.

- 자비스 모드를 켜거나 자비스 설정을 바꾸기
- 위임 grant를 만들거나 넓히기(grant를 거두고, 세션을 넘겨받고 되돌려 주는 것은 할 수 있습니다). 예외: 이 컴퓨터에서 **설정 > Jarvis > 위임 > 원격 웹 로그인에서 위임 허용**을 켜 두면(기본은 꺼짐), 비밀번호로 들어온 원격 로그인은 비밀번호를 다시 입력하고 세션 하나나 프로젝트 하나에 위험 항목 없이 최대 24시간짜리 grant를 줄 수 있습니다. 그러면 비밀번호를 아는 사람도 똑같이 할 수 있습니다. [원격 로그인에서 위임하기](web.md#원격-로그인에서-위임하기) 참고
- 브리핑을 켜거나 바꾸기(끄는 것은 할 수 있습니다), 자비스에게 시켜도 마찬가지
- 보안 목록이나 원격 접속 설정 자체를 바꾸기
- 외부 세션을 제한 없음으로 열거나 외부 CLI의 경로를 확인하기

이런 일은 그 컴퓨터에서 직접 하세요. 이 목록은 링크를 가진 사람을 막는 보안 경계가 아닙니다. 전체 목록과 그 목적은 [snowpea 웹](web.md#이-컴퓨터에-남겨-두는-것)에 있습니다. 원격 페이지는 암호화되지 않은 HTTP이기도 합니다. 믿을 수 없는 네트워크에서 열기 전에 그 문서의 경고를 읽으세요.

## 비서 기능

자비스는 일정, 메일, 할 일도 함께 관리할 수 있습니다. 이 기능들은 설정하기 전에는 돌아가지 않습니다.

### 브리핑

브리핑은 일정에 따라 자비스가 보내는 짧은 요약입니다. **직접 켜기 전에는 꺼져 있습니다**.

- 자비스 화면의 **브리핑**에서 켜거나, 대화로 자비스에게 브리핑을 요청합니다.
- 요일과 시각, 시간대, 브리핑에 넣을 내용(세션, 사용자를 기다리는 일, 할 일, 메일, 일정)을 고릅니다.
- 브리핑은 자비스 폴더의 `reports/` 아래에 보고서로 저장됩니다.
- 메일과 일정 항목은 연결된 메일이나 일정 프리셋이 있어야 합니다(아래 참고).

일정은 `jarvis.briefing.schedule`의 cron 식입니다. 기본값은 `0 9 * * 1-5`(평일 오전 9시)입니다. 시간대는 `jarvis.briefing.timezone`입니다. 비워 두면 데몬의 시간대를 씁니다.

### 예약 작업과 할 일

- 자비스는 예약 작업을 보고, 만들고, 바꾸고, 지우고, 실행할 수 있습니다. 예약 작업은 자기 워커 세션에서 실행되고, 결과가 자비스에게 돌아옵니다.
- 세션이나 메시지에서 본 내용 때문에 자비스가 예약 작업을 만들거나 바꾸지는 않습니다. 깨우는 메시지로 시작된 턴에서는 거부합니다. 사용자 본인의 턴에서 요청하세요.
- 할 일은 자비스 폴더에 저장됩니다. 자비스가 추가하고, 보고, 완료 처리할 수 있습니다. 할 일은 매일, 매주, 매월 반복할 수 있습니다. 반복하는 할 일에는 마감일이 있어야 합니다.

### 메일과 일정 프리셋

프리셋은 MCP 서버로 메일과 일정을 자비스에 연결합니다. 필요한 단계가 미리 정해져 있습니다. **설정 → 자비스·에이전트 → 비서 프리셋**을 열고, 프리셋을 고른 뒤 단계를 따라 하세요. 각 프리셋에는 읽기 도구와, 바꾸거나 보내는 도구가 나와 있습니다.

읽기 도구는 묻지 않고 실행됩니다. 보내거나, 답장하거나, 지우거나, 옮기거나, 무엇인가를 바꾸는 도구는 항상 사용자에게 묻고, 자비스는 결정할 수 없습니다.

| 프리셋 | 연결하는 것 | 필요한 것 |
|---|---|---|
| **Google (Gmail과 캘린더)** | Google이 제공하는 원격 MCP 서버로 Gmail과 Google 캘린더 | 본인의 Google Cloud 프로젝트에서 만든 OAuth 클라이언트 ID와 클라이언트 보안 비밀. 그 프로젝트에서 Gmail MCP API와 Calendar MCP API를 켜야 합니다. OAuth 클라이언트는 "AI 기반 에이전트 사용"으로 표시해야 합니다. Google 서버는 개발자 미리 보기(Developer Preview) 단계입니다. 로그인할 계정으로 미리 보기에 참여하세요. |
| **Microsoft 365 (Outlook 메일과 캘린더)** | Outlook 메일과 캘린더 | 기기 코드로 한 번 로그인합니다. 개인 계정이면 테넌트 ID를 비워 두거나 `consumers`를 입력합니다. 회사 계정은 관리자 승인이 필요할 수 있습니다. 처음 시작할 때 `npx`로 서버를 내려받으므로, 데몬이 도는 컴퓨터에 Node.js가 있어야 합니다. |

Google 읽기 도구는 스레드 검색과 읽기, 라벨과 초안 목록, 캘린더와 일정 목록, 일정 조회, 시간 추천입니다. 초안 작성, 라벨 변경, 모든 캘린더 변경은 먼저 묻습니다. Gmail 서버에는 보내기 도구가 없어서 이 서버로는 메일을 보낼 수 없습니다.

Microsoft 365 읽기 도구는 메일, 폴더, 규칙의 목록과 읽기, 캘린더 목록과 일정 목록, 가능한 회의 시간 찾기, 로그인 확인입니다. 보내기, 답장, 전달, 옮기기, 삭제, 규칙 변경, 캘린더 변경과, 원본 메일 파일이나 첨부 파일 가져오기는 항상 묻습니다.

**Microsoft 365 프리셋의 위험을 알고 쓰세요.** 이 프리셋은 Microsoft가 아닌 커뮤니티 서버 `@softeria/ms-365-mcp-server`를 씁니다. 서버는 사용자 계정의 권한으로 실행됩니다. snowpea는 서버의 버전을 고정하지만 그 의존 패키지의 버전은 고정하지 않습니다. 서버를 내려받을 때 npm 설치 스크립트는 실행하지 않습니다.

Microsoft 365 로그인은 데몬이 도는 컴퓨터에서 한 번 실행하는 명령입니다.

```text
npx -y --ignore-scripts @softeria/ms-365-mcp-server@<고정된 버전> --login --preset mail,calendar
```

설정 화면에는 고정된 버전이 들어간 정확한 명령이 나옵니다. 그 명령을 복사하세요. 명령은 짧은 코드와 Microsoft 주소를 출력합니다. 브라우저에서 주소를 열고 코드를 입력해 로그인한 뒤 **로그인 확인**을 누릅니다.

프리셋을 제거하면 그 서버, 권한 태그, 저장된 클라이언트 보안 비밀, 예약 루틴이 지워집니다. Microsoft 계정에서 로그아웃되지는 않습니다. 서버는 자기 로그인을 유지하며, snowpea는 프리셋을 제거할 때 이 점을 알려 줍니다.

### 메일 정리는 격리된 워커에서

메일 작업이 실행되면 워커 세션이 메일을 읽습니다. 워커는 그 프리셋의 읽기 도구만 받고, 빈 임시 폴더를 쓰며, 위임, 메모리, 다른 권한은 받지 않습니다. 자비스는 워커의 요약만 받습니다. 워커의 기록은 실행이 끝나면 지워집니다. 메일 내용이 자비스의 결정에 섞이지 않습니다.

## 음성

자비스에게 누르고 말하기(push-to-talk)로 말할 수 있습니다.

1. 단축키, 기본은 **Ctrl+Shift+Space**를 누르고 있거나, 입력창의 마이크 버튼을 누르고 있습니다.
2. 키나 버튼을 누른 채 말합니다.
3. 키나 버튼에서 손을 뗍니다. 손을 떼면 전송됩니다(**떼면 보내기**). 녹음 중에 Esc를 누르면 녹음이 취소됩니다.

단축키와 떼면 보내기 동작은 **설정 → 오디오 → 누르고 말하기**에서 바꿉니다. 같은 화면에 자비스의 답을 소리 내어 읽는 옵션도 있습니다. 음성 설정은 [음성](voice.md)을 보세요.

## 자비스가 시작하는 브라우저 세션

snowpea 브라우저가 실행 중이면, 자비스가 브라우저에서 일하는 세션을 시작할 수 있습니다. "브라우저에서 해 줘"라고 요청하세요. 이 세션은 브라우저 루틴과 똑같이 브라우저의 도구로 돌고, 작업 내용으로 제목이 붙고, 공유된 상태로 시작합니다. 규칙:

- 브라우저가 연결되어 있을 때만 됩니다. 아니면 자비스가 브라우저가 실행 중이 아니라고 알려 줍니다.
- 한 번에 하나만 돌립니다. 실행 중인 브라우저 세션이 끝나야 다음 세션을 시작합니다.
- 자비스가 시작하는 다른 세션처럼, 사용자의 요청이나 맡긴 일 안에서만 시작합니다. `jarvis.exposeBrowser`가 꺼져 있으면 시작하지 않습니다.
- 그 세션의 메시지는 사용자가 아니라 자비스의 메시지로 표시되므로, 브라우저의 "사람만" 규칙이 그대로 지켜집니다.
- 브라우저가 묻는 승인은 다른 요청과 똑같이 위임을 따릅니다. 페이지 조작, 보내기, 업로드는 "비밀·보내기" 종류입니다. **결제, 정기 구매, 사용자 자신의 탭 사용은 언제나 사용자의 몫입니다.** 자비스는 항상 한 번만 허용합니다.
- 브라우저 연결이 끊기면 세션은 기다리지 않고 안내와 함께 끝납니다.

## 자비스 아래의 외부 에이전트 CLI

자비스는 Claude Code, Codex, agy, Cursor agent의 세션을 읽을 수 있고, 위임 규칙 안에서 지시할 수도 있습니다. 이 영역에서 사용자가 직접 확인해야 하는 네 가지가 있고, 자비스는 어느 것도 할 수 없습니다.

- **프로젝트 신뢰.** snowpea가 외부 CLI를 시작하려면 사람이 먼저 그 프로젝트를 신뢰해야 합니다. 자비스는 이 신뢰를 줄 수 없습니다.
- **CLI 경로 확인.** CLI에 지정한 경로는 사용자가 확인한 뒤에만 실행됩니다.
- **제한 없음 선택.** 사용자만 고를 수 있고, 한 번에 세션 하나에만 적용됩니다.
- **CLI에 넘길 변수 이름 정하기.** `passEnv`는 사용자만 정합니다.

방법은 [외부 세션](external-sessions.md) 문서에 있습니다.

## 설정 참고

자비스 설정은 `settings.json`의 `jarvis` 아래에 있습니다. 프로젝트별 노출은 프로젝트마다 정합니다. 표의 값은 기본값입니다.

| 설정 | 기본값 | 역할 |
|---|---|---|
| `jarvis.enabled` | `false` | 자비스 모드를 켭니다. |
| `jarvis.model` | `null` | 자비스가 쓸 모델 프로필. `null`이면 `models.default`를 따릅니다. |
| `jarvis.folder` | `~/Snowpea/Jarvis` | 자비스의 작업 폴더. 자비스가 쓸 수 있는 유일한 폴더입니다. |
| `jarvis.delegation.default` | `staged` | 위임이 없을 때의 수준. `staged`만 받습니다. |
| `jarvis.delegation.projectTtlHours` | `24` | 만료를 정하지 않은 프로젝트 위임의 유효 시간(시간 단위). |
| `jarvis.quietMinutes` | `10` | 세션에 입력한 뒤 사용자 입력이 없을 때 자비스가 돌아오기까지의 시간(분). |
| `jarvis.stallMinutes` | `15` | 완전히 맡긴 세션이 멈춰 있을 때 자비스가 살펴보기까지의 시간(분). |
| `jarvis.exposeBrowser` | `true` | 브라우저 세션을 자비스와 공유할 수 있는지 정합니다. 끄면 브라우저 세션은 자비스에게 숨겨지고 스위치가 잠깁니다. |
| `jarvis.sessions.default` | `off` | 새 세션을 자비스와 공유된 상태(`on`)로 시작할지, 아닌 상태(`off`)로 시작할지 정합니다. 이 컴퓨터에서 사용자만 바꿀 수 있습니다. |
| `jarvis.proactive.finished` | `true` | 세션이 끝나면 알립니다. |
| `jarvis.proactive.error` | `true` | 세션이 실패하거나 오류로 멈추면 알립니다. |
| `jarvis.proactive.needsYou` | `true` | 사용자의 결정이 필요하면 알립니다. |
| `jarvis.proactive.decided` | `true` | 자비스가 대신 결정하면 알립니다. |
| `jarvis.briefing.enabled` | `false` | 예약 브리핑을 켭니다. |
| `jarvis.briefing.schedule` | `0 9 * * 1-5` | 브리핑의 cron 식(브리핑 시간대 기준). |
| `jarvis.briefing.timezone` | `null` | 브리핑의 시간대. `null`이면 데몬의 시간대를 씁니다. |
| `jarvis.briefing.sections` | `sessions`, `waiting`, `todos`, `mail`, `calendar` | 브리핑에 넣을 내용. |
| `jarvis.briefing.instructions` | 비어 있음 | 브리핑에 추가로 줄 지시. |
| `jarvis.budget.wakesPerHour` | `30` | 한 시간에 자비스를 깨울 수 있는 횟수. |
| `jarvis.budget.dailyTokens` | `2000000` | 하루(현지 날짜 기준)에 자비스가 쓸 수 있는 토큰 수. `0`이면 제한이 없습니다. |
| `jarvis.messenger.route` | `true` | 자비스 모드가 켜져 있는 동안 연결된 메신저 채팅을 자비스로 보냅니다. |
| `jarvis.messenger.allowGrants` | `true` | 메신저에서 위임 확정을 허용합니다. |
| `jarvis.notify.inApp` | `true` | 앱과 터미널 UI에 알림을 표시합니다. |
| `jarvis.notify.os` | `true` | 중요도 보통 이상의 알림을 운영체제 알림으로 보냅니다. |
| `jarvis.notify.messenger` | `true` | 중요도 높음과 긴급 알림을 본인의 개인 메신저 채팅으로 보냅니다. |
| `jarvis.external.enabled` | `true` | 자비스 아래의 외부 에이전트 세션을 허용합니다. |
| `jarvis.external.maxProcesses` | `4` | snowpea가 동시에 실행할 CLI 프로세스 수의 최대치(1~32). |
| `jarvis.external.idleSec` | `900` | 쉬고 있는 CLI 프로세스를 멈추기 전까지 두는 시간(초). |
| `jarvis.external.clis.<id>.enabled` | `true` | 이 CLI를 씁니다(`claude`, `codex`, `agy`, `cursor`). |
| `jarvis.external.clis.<id>.path` | `null` | 실행 파일 경로. `null`이면 `PATH`에서 찾습니다. 직접 지정한 경로는 확인한 뒤에만 실행됩니다. |
| `jarvis.external.clis.<id>.defaultMode` | `null` | 새 세션이나 이어 가는 세션이 시작할 모드. `null`이면 CLI의 기본 모드입니다. 제한 없음은 기본값이 될 수 없습니다. |
| `jarvis.external.clis.<id>.passEnv` | `[]` | 이 CLI에 넘길 환경 변수 이름. API 키 변수 같은 것입니다. |

사용자만 정할 수 있는 설정도 있습니다. `jarvis.external.clis.<id>.defaultMode`와 `passEnv`는 사용자만 바꿀 수 있고, snowpea가 바뀔 때마다 기록합니다. 차단 명령과 보호 폴더 목록은 `security` 아래의 별도 설정입니다. [보안 목록](security.md)을 보세요.

## 보안 참고 사항과 알려진 제한

자비스 모드는 베타입니다. 의지하기 전에 다음 제한을 알아 두세요.

- **데몬 토큰 하나.** 같은 컴퓨터의 데스크톱 앱, IDE, 터미널 UI, 브라우저 호스트, 원격 커넥터는 모두 snowpea 홈 폴더의 같은 데몬 토큰 파일을 씁니다. 지금은 로컬 클라이언트를 서로 구별하지 못합니다. 따라서 그 파일을 읽을 수 있는 로컬 프로그램은 사용자로 취급됩니다. 클라이언트마다 따로 인증 정보를 두는 것은 앞으로의 과제입니다. 원격 웹 접속으로 들어온 로그인은 다릅니다. 그런 연결은 모두 원격 로그인으로 표시되고, 자비스·보안·원격 접속 설정과 새 위임 grant가 거부됩니다. 이 컴퓨터에서 원격 로그인의 제한된 grant를 허용해 둔 경우는 예외입니다([다른 컴퓨터에서 자비스 쓰기](#다른-컴퓨터에서-자비스-쓰기) 참고).
- **분류기는 명령줄만 봅니다.** 자비스는 명령, 인자, 가리키는 파일 경로로 행동을 판단합니다. 스크립트나 프로그램이 실행된 뒤 내부에서 무엇을 하는지는 볼 수 없습니다. 파일을 지우는 스크립트도 명령줄만 보면 안전해 보이면 안전한 명령으로 실행될 수 있습니다. 보안 목록도 같은 명령줄을 확인하므로 같은 한계가 있습니다. 확인할 수 없는 줄은 사용자에게 갑니다.
- **제한 없음 모드의 외부 CLI.** snowpea는 제한 없음 모드의 CLI가 무엇을 하는지 통제하지 않습니다. 자비스는 그런 세션을 읽고 요약할 수는 있지만, 지시하거나 새로 시작할 수는 없습니다. 위험 항목 규칙과 보안 목록도 그 안에는 적용되지 않습니다. 제한 없음은 사용자만 고를 수 있고, 한 번에 세션 하나에만 적용됩니다.
- **다른 도구의 기록 형식은 바뀔 수 있습니다.** Claude Code, Codex, agy, Cursor agent는 세션 기록 형식을 공개 규격으로 내놓지 않습니다. CLI 버전이 바뀌면 형식도 바뀔 수 있습니다. snowpea는 CLI 버전을 확인하고, 세션을 읽지 못하면 오류 안내를 보여 줍니다.
- **브라우저 세션.** 1.56.0부터 사용자가 공유한 브라우저 세션은 다른 세션처럼 위임을 따릅니다. 페이지 조작, 보내기, 업로드는 "비밀·보내기" 종류라서, 그 종류를 맡겼을 때만 자비스가 결정합니다. 결제, 정기 구매, 사용자 자신의 탭은 언제나 사용자의 몫입니다. core는 이를 브라우저의 동작 이름(`payment.*`, `subscription.*`, `purchase.*`, `recurring…`, `checkout`, `use_tab`, 또는 `risk: payment`)으로 알아봅니다. 다른 이름을 쓰는 동작은 그 종류로 판단합니다.
- **Windows.** tmux 공유 터미널은 Windows에서 쓸 수 없습니다. 외부 CLI 프로세스는 자기 콘솔 창을 띄우지 않고, snowpea가 CLI를 멈출 때는 그 CLI의 프로세스 트리 전체를 함께 끝냅니다. 데몬이 비정상 종료한 뒤 남은 외부 CLI 프로세스는 프로세스 시작 시각을 읽을 수 있어야 정리하는데, Windows에서는 읽을 수 없습니다. 그래서 그런 프로세스는 직접 끝내기 전까지 남아 있습니다.
- **자비스는 URL을 가져오지 않습니다.** 짧은 검색어로만 웹을 검색합니다. 붙여 넣은 링크를 열어 보지 않습니다.
- **자비스는 snowpea 자체 파일을 읽지 않습니다.** 읽기 범위에서 snowpea 홈 폴더와, 링크된 `settings.json` 이 가리키는 파일을 뺍니다. 검색 결과에서도 비밀 파일의 줄은 빠집니다.
- **위험 항목도 실수할 수 있습니다.** 확정한 위임은 화면에 보인 그대로 적용됩니다. 확정하기 전에 범위와 위험 항목을 꼭 확인하세요.
