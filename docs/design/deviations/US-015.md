# Deviations — US-015 (M5 스케줄러 / 데몬 keepalive / `job.*`)

`docs/design/m5-memory-scheduler-gateway-contract.md` §2·§4, 플랜 §2.6, AC-08·AC-20의 잡 부분에 대한 기록.
계약 문서를 동시에 고치면 섹션이 유실되므로 여기에만 적는다.

1. **`schedule_*` 툴이 `tools/schedule.py`가 아니라 `scheduler/tools.py`에 있다.** 리드 지시는 US-009가
   `tools/schedule.py`에 비활성 스텁을 두면 그 본문을 바꾸라는 것이었는데, US-009는 스텁을
   `tools/stubs.py`(공용 파일, 소유자 아님)에 넣었고 `tools/schedule.py`는 끝내 생기지 않았다. 그래서 폴백
   경로를 택했다: `scheduler/tools.py`가 `register_schedule_tools(registry)`를 제공하고,
   `wire_scheduler`가 빌트인 카탈로그 등록 **이후에** 호출해 같은 이름으로 덮어쓴다(메모리 툴이 쓰는 방식과
   동일). 이름·카테고리(`schedule`)·권한 태그(`send`)는 스텁이 약속한 그대로다. 입력 스키마는 `spec`/`task`로
   바뀌었지만 스텁의 `cron`/`prompt`도 계속 받는다.
2. **`IMPLEMENTED_METHODS` / `HANDLED_METHODS` 이름.** 지시문의 `IMPLEMENTED_METHODS`는
   `server/protocol.py`의 프로토콜 상수이고, 핸들러 모듈 쪽 상수 이름은 `HANDLED_METHODS`다. 둘 다 갱신했다
   (`server/job_handlers.py`의 `HANDLED_METHODS`, `protocol.IMPLEMENTED_METHODS`에 `job.*` 4개).
3. **`job.*` 핸들러는 새 모듈 `server/job_handlers.py`에 있다.** US-014가 `server/session_handlers.py`를
   동시 편집 중이어서 US-013과 같은 이유로 분리했다. `build_dispatcher`가
   `register_session_handlers` 바로 다음에 `register_job_handlers`를 부른다(한 줄).
4. **프로토콜 추가 필드(모두 additive, 기본값 있음).**
   `JobInfo`에 `kind`·`enabled`·`lastRunAt`·`lastStatus`, `JobScheduleParams`에 `agent`·`workdir`,
   `JobScheduleResult`에 `nextRunAt`, `LifecycleStatus`에 `reasons`·`summary`를 더했고
   `JobEventNotification.kind`를 `str` → `Literal["started","finished","failed","denied"]`로 좁혔다.
   계약 §2의 `last_status`·`next_run`을 와이어에 실으려면 필요했다. `gen_protocol.py`를 같은 변경에서 돌렸다.
5. **`Job`에 계약에 없는 칸 세 개가 있다.** `state`(`scheduled|running|cancelled`, `JobInfo`가 이미 요구),
   `workdir`(잡이 도는 디렉터리 — 없으면 `$SNOWPEA_HOME`), `agent`(M7에서 쓸 자리). `cancel`은 행을 지우지
   않고 `enabled=0, state='cancelled'`로 바꾼다. 실행 이력(`job_runs`)을 남겨야 이중 발화 가드가 계속 유효하다.
6. **`Scheduler.cancel`은 삭제가 아니라 비활성화다.** 계약이 "cancel"이라고만 하는데, 취소된 잡을
   `job.list`에서 지워버리면 사용자가 방금 뭘 껐는지 확인할 수 없다. `lifecycle.jobs` 카운터는 `enabled=1`인
   잡만 센다(플랜 §2.6 문구 그대로).
7. **NL 파싱은 직접 썼다(Hermes vendoring 없음).** `/tmp/hermes-ref/cron/jobs.py`의 `parse_schedule`은 영어
   전용이고 자기네 저장 딕셔너리와 얽혀 있어서, 한국어 케이스를 얹는 비용이 새로 쓰는 비용보다 컸다.
   `cron/occurrences.py`의 "occurrence key" 아이디어만 가져왔고 코드는 복사하지 않았으므로 vendoring 맵에
   추가 항목이 없다. 유일한 외부 의존은 이미 `pyproject.toml`에 있던 `croniter`다.
8. **시계는 로컬 타임존, 저장은 UTC.** "매일 09:00"은 데몬이 도는 기계의 아침 9시를 뜻한다. cron 평가와 NL
   시각 해석은 로컬 aware datetime으로 하고, `jobs.next_run`·`last_run`·`job_runs.scheduled_ts`는 UTC ISO-8601
   (`...Z`)로 적는다.
9. **`once` 잡은 한 번 돌면 스스로 꺼진다.** `next_run`이 `None`이 되고 `enabled=0`이 되므로 `lifecycle.jobs`에서
   빠진다. 계약이 명시하지 않았지만, 그러지 않으면 "in 60s" 잡 하나가 데몬을 영원히 붙잡는다.
10. **`job.runNow`는 스케줄을 건드리지 않는다.** 동기적으로 끝까지 돌고(`Ok`가 돌아올 때 이미 실행 완료),
    `last_run`/`last_status`만 갱신하며 `next_run`은 그대로 둔다. AC-08이 "`job.list`에 마지막 실행 시각 기록"을
    확인하는 방식이 이것이다. CLI는 이 호출에만 별도로 긴 데드라인(`JOB_RUN_TIMEOUT_SEC = 900s`)을 쓴다.
11. **`last_status` 판정은 세션 이벤트로 한다.** 잡 세션에 `_Collector`(`notify`/`closed`만 가진 가짜 커넥션)를
    `EventHub`에 붙여 `message.done`·`error`·`turn.done`을 모은다. `error{code:"approval_timeout"}`이 보이면
    `denied_by_timeout`, `turn.done{complete}`이고 에러가 없으면 `ok`, 나머지는 `error`. 마지막 `message.done`
    텍스트가 채널로 나가는 본문이다.
12. **`job.event`는 `EventHub.notify`로 보낸다.** 계약의 "모든 인증된 연결"은 US-016이 `system.hello`에서
    `hub.register_client(conn)`를 부르게 만든 덕분에 그대로 성립한다. 별도의 연결 레지스트리를 만들지 않았다.
13. **배달 폴백.** `channel`이 비었거나 `log`면 `$SNOWPEA_HOME/logs/jobs.log`에 한 줄씩 적는다. 그 밖의 채널은
    `core.gateway.deliver(channel, text)`를 쓰고, 게이트웨이가 없거나 예외를 던지면 경고를 남기고 같은
    로그로 떨어진다. 잡 결과가 조용히 사라지지 않게 하기 위해서다. `Paths.jobs_log`를 새로 추가했다.
14. **auto 모드 잡 등록 승인은 툴 경로에만 있다.** `schedule_create`가 `mode="auto"`를 받으면 세션 모드가
    `auto`여서 `send` 태그가 이미 통과했더라도 `approvals.request(...)`를 따로 부른다(계약 §2). RPC
    `job.schedule`과 `/schedule`은 사용자가 직접 말한 것이므로 묻지 않는다.
15. **`Session.unattended` 필드를 추가했다.** 예전에는 `origin_conn is None`으로만 무인 여부를 알 수 있었다.
    스케줄러 세션은 이 플래그를 `True`로 세운다. 에이전트 루프의 `unattended` 인자는 그대로다.
16. **`scheduler` 설정 블록.** `settings.scheduler = {enabled, tickSec: 15, catchUpSec: 3600}`.
    `catchUpSec`은 계약 §2의 "1시간보다 늦으면 missed"를 설정값으로 옮긴 것이다.
17. **`snowpea job schedule`의 스펙 플래그.** `--at`/`--in`/`--every`/`--cron`/`--spec`이 모두 같은 argparse
    dest로 들어간다. `--in 60s`처럼 단위만 적은 값(`60s`, `10m`)은 `in 60s`로 해석하고, 나머지는 적은 그대로
    파서에 넘긴다. `snowpea job`은 이제 플레이스홀더가 아니다.
18. **`tests/test_rpc_roundtrip.py::test_unimplemented_method_reports_not_implemented`가 skip으로 바뀌었다.**
    `job.*` 4개가 구현되면서 "선언만 되고 미구현인 무인자 메서드"가 하나도 남지 않았다. 테스트의 헬퍼가
    `AssertionError("retire this test")`를 던지게 되어 있었는데, 자기 docstring의 의도대로 남은 후보가 없으면
    `pytest.skip`하도록 고쳤다. 나중에 새 무인자 메서드가 선언되면 저절로 다시 돈다.
