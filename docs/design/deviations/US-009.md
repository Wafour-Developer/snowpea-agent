# Deviations — US-009 (M2 full tool suite)

Against `docs/design/m2-tools-contract.md` §2–§8. Recorded here rather than appended to the contract, per the lead's note about concurrent edits losing sections.

Everything in §2–§8 is implemented as written except where noted.

1. **`shell` gained a `background` flag.** The contract lists `process_list` / `process_kill` without saying how a background process starts. `shell {background: true}` detaches the command on the backend (`nohup`, output to `.snowpea/logs/bg-*.log`) and records its pid in `tools/process.py`; the two process tools read and signal that registry. No new tool name was added.
2. **`web_search` catches every provider exception, not only `SearchProviderUnavailable`.** A provider client is third-party code; one raising `RuntimeError` must not take the tool down. Each failure is recorded and the chain continues, and the final error names every provider that declined.
3. **No hand-rolled JSON-RPC fallback for MCP.** §6 allows one "else a minimal JSON-RPC-over-stdio client". The `mcp` package installs cleanly (2.2.0), so stdio is implemented only through it. The session is held open by a supervisor task because `stdio_client` and `ClientSession` must be entered and exited in one task while tool calls arrive from turn tasks.
4. **SSE transport for MCP is declared, not implemented.** A server entry carrying `url` instead of `command` is parsed and reported as `transport: "sse"`, and starting it raises a clear "not implemented yet" error. §6 marks SSE optional.
5. **`tool.list` syncs MCP servers before answering.** Discovery needs a workdir, so `tool.list` syncs against the session's workdir, or the daemon's own directory when there is no session. The daemon runs with its cwd set to `$SNOWPEA_HOME`, so a session-less `snowpea tools list` sees `$SNOWPEA_HOME/.mcp.json` but not the caller's `<workdir>/.mcp.json`; the workdir file is picked up on `session.create`, which is the path the TUI and every turn take.
6. **`SessionManager` gained an `on_close` callback list.** §4 requires the per-session browser context to close with the session. `wire_core` appends `browser_providers.close_all_sessions` to it. Additive: no existing call site changed.
7. **`provider.configure` is implemented for vendor `media` only.** Other vendors still raise `not_implemented`, which US-011 (M3) fills in.
8. **Provider metas carry `endpoint` and use a tuple for `env`.** §3's dataclass lists `env: list[str]`; the registry is module-level and shared, so the field is a tuple to stay immutable. `endpoint` was added so the catalog-only ids document where they would call.
9. **Vendored `url_safety.py` is patched.** Upstream imports `hermes_constants.get_hermes_home_override` and `utils.is_truthy_value`, neither of which is vendored. Both are replaced by local shims with the same behaviour (snowpea has one config scope per daemon). The patch is recorded at `core/snowpea_core/vendor/patches/tools/url_safety.py.patch`. The other five vendored files are byte-identical to upstream.
10. **Vendored sources are excluded from ruff and mypy.** They must stay byte-identical to hermes-agent for the integrity check, so reformatting them is not an option; `scripts/verify_vendor_integrity.py` is what gates them.
