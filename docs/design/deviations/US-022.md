# Deviations — US-022 (M8 설치·번들·서비스·릴리즈·E2E)

`docs/design/m8-packaging-contract.md` §1~§4·§6, plan §3.4·§4 M8·§7.9, AC-01 기준.
계약서 본문 대신 여기에 적는 관례는 US-013 이후와 동일하다. (§5 docs/manual은 US-023 몫이라
건드리지 않았다.)

1. **sdist도 TUI 번들을 싣는다.** 계약 §1은 훅이 wheel에만 번들을 넣는다고 읽히지만,
   `uv build`는 **sdist를 먼저 만들고 그 sdist에서 wheel을 빌드**한다. sdist에 `tui/`가 없으므로
   훅이 두 번째 패스에서 복사할 원본을 잃고 빌드가 깨졌다(실제로 깨졌다). 그래서
   `[tool.hatch.build.targets.sdist]`에도 `artifacts = ["core/snowpea_core/tui/dist/snowpea-tui.js"]`를
   두고, `copy_bundle()`은 원본이 없어도 **목적지에 이미 복사본이 있으면 그것을 쓴다**. 결과는
   계약과 같다: `uv build` 한 번으로 번들이 들어간 wheel이 나온다.

2. **sdist `include`에 `installer`와 `hatch_build.py`를 더했다.** 빌드 백엔드가 sdist에서 훅을
   불러야 하므로 `hatch_build.py`는 필수고, `installer/`는 sdist만 받은 사람도 설치 스크립트를
   가질 수 있게 한 것이다.

3. **`hatch_build.py`가 hatchling import를 방어적으로 감싼다.** 로직은 hatchling을 모르는
   `copy_bundle(root, *, skip)`에 있고, 훅 클래스는 그것을 부르기만 한다. hatchling은 빌드
   환경에만 있고 `dev` 그룹에는 없으므로, 이렇게 해야 `tests/test_installer.py`가 번들 복사·누락
   실패·sdist 재사용을 **실제로** 단위 테스트할 수 있다.

4. **`--from-checkout`은 wheel이 아니라 `uv tool install --force --editable <repo>`다.** 계약은
   "editable 또는 빌드된 wheel"을 허용한다. editable을 고른 이유는 (a) CI e2e가 wheel 빌드를
   한 번 더 기다리지 않아도 되고, (b) 작업 트리를 그대로 실행하므로 E2E가 방금 만든 변경을
   검증하며, (c) 체크아웃의 `tui/dist`가 TUI 해석 3순위로 그대로 잡히기 때문이다. wheel 경로는
   릴리즈 워크플로의 `smoke-test the built wheel` 스텝이 대신 지킨다.

5. **`install.sh`에 `SNOWPEA_SKIP_PATH=1`을 추가했다.** 계약 §2의 "쉘 rc에 마커와 함께 PATH 추가"는
   그대로지만, E2E는 일회용 실행이라 사용자의 `.bashrc`를 고칠 이유가 없다. 스모크 스크립트가
   이 변수와 `UV_TOOL_DIR`/`UV_TOOL_BIN_DIR`/`SNOWPEA_HOME`을 `/tmp` 아래로 돌려서, **사용자의
   기존 snowpea 설치·데몬·쉘 설정을 전혀 건드리지 않는다**.

6. **Windows 기본 홈은 `paths.py`가 아니라 `install.ps1`이 정한다.** 계약 §2가 요구한
   `%LOCALAPPDATA%\snowpea`를 설치 스크립트가 사용자 환경변수 `SNOWPEA_HOME`으로 심는다.
   `config/paths.py`의 기본값(`~/.snowpea`)은 US-022 소유 파일이 아니고, 이미 `SNOWPEA_HOME`을
   존중하므로 코드 변경 없이 계약을 만족한다.

7. **E2E 12단계는 "백엔드가 docker로 바뀌었다"까지만 assert 한다.** plan §7.9는 "hostname 상이"를
   적지만, CLI는 `-c` 호출마다 **새 세션**을 열므로 `/backend docker` 다음 턴은 이미 다른
   세션이다. 한 턴 안에서 hostname을 비교할 방법이 없어서, 컨테이너가 정말 다른 호스트라는
   사실은 이미 그것을 검증하는 `tests/test_backends.py`에 맡기고 여기서는 `backend.changed`
   이벤트를 확인한다(그래서 `--json`으로 돌린다). docker가 없으면 SKIP.

8. **7·8단계의 "명령 없음" 판정은 레지스트리 조회로 한다.** 셸의 `command not found`가 아니라
   `snowpea commands list --json`에 `ralph`/`team`이 있는지를 본다. 슬래시 명령은 데몬 안에
   등록되는 것이라 셸 종료 코드로는 "아직 안 붙었다"와 "붙었는데 깨졌다"를 구분할 수 없다.
   등록되어 있으면 반드시 assert 하고, 없을 때만 `SKIP 7 (pending US-019)` / `SKIP 8 (pending US-020)`을
   찍는다. (실행 시점에는 둘 다 등록되어 있어 PASS 했다.)

9. **2단계 벤더는 `deepseek`이다.** 스크립트가 `--vendor <v> --key $KEY`로 적은 자리에 키가 필요
   없는 실벤더를 하나 골라야 했다. 실제 모델 호출은 전부 `SNOWPEA_PROVIDER=fake:…/e2e.json`이
   가로채므로 이 값은 "설정이 settings.json에 기록되는가"만 증명한다.

10. **`PROTOCOL_VERSION`은 아직 `0.1.0` 그대로다.** 계약 §4는 "v0.1.0 **릴리즈 커밋**에서 1.0.0으로
    올린다"고 적었고, 지금 올리면 진행 중인 다른 스토리의 클라이언트 핸드셰이크를 깬다. 대신
    `release.yml`이 **`v1*` 태그에서 `PROTOCOL_VERSION`이 0.x면 릴리즈를 거부**하도록 게이트를
    넣었고, 워크플로 상단 주석에 순서를 적었다.

11. **`resolve_tui_command()`에 keyword-only 인자 `package_root`/`repo_root`를 더했다(가산).**
    기본값은 기존 동작과 100% 같고(설치된 패키지 디렉터리, 체크아웃 루트), 호출부도 그대로다.
    해석 순서(`SNOWPEA_TUI_ENTRY` → 패키지 → 체크아웃)를 실제 파일로 테스트하기 위한 이음매다.
    같은 이유로 `packaged_tui_bundle()`/`repo_tui_bundle()`을 노출했다.

12. **`installer/brew/snowpea.rb`는 의도적으로 스텁이다.** PyPI 등록과 태그 tarball의 sha256이
    생기기 전에는 `url`/`sha256`을 채울 수 없어 자리표시자를 두었고, 파일 주석에 그 사실과
    `brew audit`이 불평할 것이라는 점을 적었다. 계약 §2도 "formula stub"을 요구한다.

13. **`install.ps1`과 `v01_smoke.ps1`은 이 머신에서 실행 검증하지 못했다.** 리눅스 개발 환경에
    `pwsh`가 없어 문법 파싱조차 로컬에서 돌릴 수 없었다. `tests/test_installer.py`는 두 파일의
    필수 요소(winget 패키지 id, `%LOCALAPPDATA%`, `SNOWPEA_HOME`)를 정적으로만 검사한다.
    **첫 실제 실행은 CI의 `e2e-windows` 잡**이며, 거기서 깨지면 그 잡이 잡는다.

14. **`snowpea service`의 `--home` 전달.** 계약 §3의 `ExecStart=<snowpea-core path> --port 0`에
    더해, 설치 시점에 `SNOWPEA_HOME`이 설정돼 있으면 `--home <경로>`를 유닛에 굳혀 넣는다.
    서비스는 로그인 세션의 환경변수를 물려받지 않으므로, 이게 없으면 사용자가 쓰던 홈이 아니라
    `~/.snowpea`로 붙는다. `snowpea-core`가 PATH에 없으면 `sys.executable -m snowpea_core`로
    적어 체크아웃·venv 설치도 동작한다.

15. **`PLACEHOLDER_SUBCOMMANDS`에서 `service`를 뺐다.** `team`은 US-020이 같은 커밋 창에서 빼서
    현재 이 튜플은 비어 있다. 자리표시자 배선(파서 등록 루프, dispatch 분기)은 그대로 두었다 —
    다음에 또 필요할 때 쓰라고.
