# Deviations — US-017 (Claude Code plugin loader, SKILL.md commands, hooks, marketplaces)

Against `docs/design/m6-m7-skills-agents-contract.md` §1 and §7, and plan AC-10 / AC-14. Recorded here rather than appended to the contract, per the lead's note about concurrent edits losing sections.

1. **`SkillLoader.reload()` is a coroutine.** It starts plugin MCP servers and broadcasts `commands.changed`, both of which are async. `wire_core` is synchronous, so the loader also exposes `load_sync()` — scan plus command registration, no network, no MCP — which is what the daemon calls while assembling `Core`; `Daemon.start` then awaits one full `reload()`. US-018 should `await core.skills.reload()`.

2. **`CommandSource` is now `str`, not `Literal["builtin", "skill", "plugin"]`.** A plugin names itself, so the contract's `plugin:<name>` label cannot be a closed literal. `CommandInfo.source` and `SkillInfo.source` carry `builtin`, `global`, `project`, `plugin:<name>`, or the marketplace name for a search hit. This widens the generated TypeScript from a union to `string`.

3. **`SkillInfo` gained `kind`, `id` and `installSpec`; a `skill.remove` method was added.** `kind` is the contract's `skill|agent|command|plugin` discriminator, `id`/`installSpec` are what AC-14 needs to feed a search hit back into `skill.install`. `skill.remove` exists because the contract's CLI has `snowpea skill remove` but the protocol had no method for it. All additive, all defaulted.

4. **`allowed-tools` is enforced, via `Session.allowed_tools`.** The contract allowed recording a deviation instead. Rather than skip it, `ToolRegistry.active(session)` now filters on `session.allowed_tools` (`None` means every tool) and the agent loop refuses a call outside the set. A skill command sets it for the duration of its turn and restores it afterwards. Six lines across `session/session.py`, `tools/registry.py` and `agent/loop.py`.

5. **`CommandContext.handled_turn`.** A skill command *is* a turn: it runs `agent_loop.run_turn` with the command's own `turn_id`, so `CommandRegistry.run` would have emitted a second `turn.done` for the same id. The flag tells the registry the turn already ended itself. Also added `CommandRegistry.unregister(name)` so a reload can drop the previous generation of skill commands.

6. **Plugin MCP servers go through `mcp_client.register_config(core, config)`.** `sync_tools`' inner loop was extracted into that function and now calls it; the loader registers a plugin's `.mcp.json` entries through the same path, so there is still exactly one place that turns an MCP server into tools. `sync_tools` itself is unchanged in behaviour.

7. **Hooks run around the tool-execution site only.** `PreToolUse` fires after the permission verdict and after the `tool.call` event, `PostToolUse` right after the tool returns, `Stop` when the turn ends with no further tool calls. A `PreToolUse` exit status of 2 produces a `tool.result` with `ok:false` and `error` prefixed `hook_blocked: `, and the turn continues (the model sees the refusal) rather than ending. Hook events other than these three are parsed and ignored.

8. **Marketplaces are registered in `$SNOWPEA_HOME/marketplaces.json`, not in `settings.json`.** `settings.py` was being edited by three other stories; a standalone file keeps the merge surface at zero. It seeds itself with the oh-my-claudecode marketplace when absent. `marketplace.load_marketplaces` / `save_marketplaces` are the API.

9. **Search endpoints.** `agentskills.io` → `GET https://agentskills.io/api/v1/skills?q=<query>`; `hermes-hub` → `GET https://hermes-hub.ai/api/v1/skills?q=<query>`; `claude-marketplace` → the `marketplace.json` of each registered repo. Both hosted endpoints are documented guesses: neither publishes a stable public search API today, so they are behind `marketplace.FETCHER` and a source that fails contributes nothing instead of failing the search. Adjust the two constants when the real endpoints are known. `skills/registry_client.py` is the snowpea.ai (v0.3) interface plus a stub that returns `[]`, wired in as a fourth source already.

10. **No YAML dependency.** PyYAML is not in `pyproject.toml`, so `skills/skill_md.py` parses the front-matter subset the format actually uses (scalars, quoted scalars, booleans, inline `[a, b]` lists, `- item` block lists). Anything else stays a string.

11. **Fixture plugin carries its own MCP server and uses `${SNOWPEA_PYTHON}`.** `skill.install` copies the plugin into `$SNOWPEA_HOME/plugins/<name>`, so a relative path back to `tests/fixtures/mcp/echo_server.py` would not resolve after installation; the fixture ships a copy at `sample-plugin/mcp/echo_server.py` and references it as `${CLAUDE_PLUGIN_ROOT}/mcp/echo_server.py`. The command is `${SNOWPEA_PYTHON}` rather than the contract's literal `python3`, expanded by the loader to `sys.executable`, because the server needs the interpreter that has the `mcp` package. `${CLAUDE_PLUGIN_ROOT}`, `${SNOWPEA_PLUGIN_ROOT}` and `${SNOWPEA_PYTHON}` all expand, with and without braces.

12. **Precedence order.** builtin → global (`$SNOWPEA_HOME/{skills,agents,commands}`) → plugins (`$SNOWPEA_HOME/plugins/*`) → project (`<workdir>/.claude` then `<workdir>/.snowpea`); later wins. Plugins sit inside the global group as the contract puts them, which means a project skill overrides a plugin skill of the same name. Project roots are scanned for every open session's workdir, plus the daemon's own directory when no session is open.

13. **`tests/test_headless_exit_codes.py::test_placeholder_subcommand_exits_two` now uses `service`.** It asserted that `snowpea skill` was an unimplemented placeholder; `skill` is implemented here, so the placeholder assertion moved to a subcommand that still is one, and a new test asserts `snowpea skill` with no action is a usage error.

14. **`skill.search` reports unreachable sources.** `SkillSearchResult` gained `unavailable: list[str]` (`"<source>: <reason>"`), because an empty result offline is otherwise indistinguishable from "nothing matched". `marketplace.search` returns a `SearchReport`; `SkillLoader.search` returns `(hits, unavailable)`. The CLI prints each unreachable source to stderr and says how many sources were unreachable when nothing matched. Additive on the wire.

15. **The CLI makes a local install source absolute.** The daemon runs in `$SNOWPEA_HOME`, so AC-10's `snowpea skill install ./tests/fixtures/plugins/sample-plugin` would otherwise resolve against the wrong directory. `cli/commands.py::resolve_install_source` resolves an existing local directory and passes everything else (git URLs, `<marketplace>/<plugin>`, shortcuts) through untouched. The server accepts absolute paths and clone URLs as before, and its "could not resolve" error now names every accepted form and the directory a relative path would have been resolved against.

16. **TUI.** `commands.changed` is wired through `TuiClient` (`onCommandsChanged`) into `app.tsx`, which calls `SlashRegistry.refresh()` and dispatches the new table. `slash/registry.ts` needed no change — it already had `refresh()` for exactly this.
