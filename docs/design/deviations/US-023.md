# Deviations — US-023 (Hermes-level multilingual documentation)

Against `docs/design/m8-packaging-contract.md` §5 and the US-023 acceptance criteria. Recorded here rather than appended to the contract, per the deviations-log convention.

1. **The manual is one page tree per language, not one page with two language sections.** The M8 contract §5 says "Korean + English sections per page (ko first)". The US-023 acceptance criteria instead ask for `docs/manual/en/` and `docs/manual/ko/` as separate trees, plus partial `ja`, `zh-CN` and `es`. The criteria win, and they are also the better shape: a bilingual page doubles scroll length for every reader, and it makes the `ja`/`zh-CN`/`es` subset impossible to express. `docs/manual/README.md` is the cross-language index that the single-page layout would not have needed.

2. **`ALLOWLIST` in `scripts/check_docs_cli.py` carries four entries.** The docs describe `snowpea team status` (US-020) and `snowpea service install|uninstall|status` (US-022). At verification time `snowpea team --help` and `snowpea service --help` are placeholder parsers with no actions, so the checker would reject those four chains. Each entry names its story and must be deleted when the story lands; `tests/test_docs_cli.py::test_allowlist_entries_name_a_story` fails an entry that does not name one. Nothing else is allowlisted.

3. **`/team` is documented although `command.list` does not yet contain it.** `uv run snowpea commands list --json` returns 20 commands at verification time and `team` is not among them (US-020 is in flight). The checker validates CLI invocations, not slash commands, so no allowlist entry was needed — but the commands page and both READMEs describe `/team <n> <task>` as the contract and AC-16 specify it. If US-020 lands with a different argument shape, `docs/manual/{en,ko}/commands.md` and the README command lists need one edit each.

4. **`installer/` does not exist yet, and the install URLs are still the canonical ones.** US-022 is in flight; `installer/install.sh` and `install.ps1` were not on disk when these docs were written. Every install URL is reproduced exactly as plan AC-01 and M8 contract §2 fix it (`https://raw.githubusercontent.com/Wafour-Developer/snowpea-agent/main/installer/...`). These are absolute URLs, so the link checker does not resolve them; they will start working when US-022 pushes the files. `docs/manual/*/install.md` also documents `--dry-run` and `uv tool install snowpea-agent`, both from the M8 contract rather than from observed behaviour.

5. **Fenced blocks tagged `text` are excluded from the CLI scan.** `docs/manual/{en,ko}/index.md` contains a schematic that pairs `snowpea`, `snowpea -c "..."` and `snowpea <subcommand>` with prose explanations. It is not paste-able, so it is tagged `text`, and `SHELL_LANGUAGES` in the checker excludes that tag. Untagged blocks are still scanned, so this is an explicit opt-out rather than a hole: a real command cannot hide in an untagged block.

6. **The checker validates subcommand chains and flag names, not argument values.** `snowpea -c "x" --mode turbo` passes, because `--mode` is a real flag; argparse would reject the value at runtime. Extending to choice sets means parsing `{plan,accept,auto}` out of help text and tracking which flag owns it, which is more fragile than the value it adds. Flags that take a value are detected (from the metavar in the option listing) so that the value token is skipped rather than mistaken for a subcommand.

7. **The link check is part of the same script, and covers HTML attributes too.** The acceptance criteria ask for "a link check that every relative link in README*.md and docs/manual resolves". It is implemented in `check_docs_cli.py` alongside the CLI check, covers Markdown links and images plus `href=`/`src=` in inline HTML (the language bar and badges are inline HTML), and skips absolute URLs and bare anchors. `--skip-cli` runs the link half alone, for environments where the CLI cannot start.

8. **Vendor id `local`, not `local-vllm`/`local-ollama`/`local-lmstudio`.** Plan §3.1 lists three local preset names; the shipped `provider.list` returns one vendor, `local`, labelled "OpenAI-compatible local (vLLM / Ollama / LM Studio)", which matches the M3 contract §1 note that they are `base_url` variants of one id. The docs follow what the CLI actually returns.

9. **The comparison table is hedged in the text.** The acceptance criteria ask for a comparison against Claude Code, Codex, opencode and Hermes. Every row describes snowpea accurately from this repository; the other four columns are summarised from their public documentation and carry a sentence below the table saying so, because those projects change faster than this README will.

10. **`snowpea provider login <vendor>` is documented as primary, `snowpea setup --login <vendor>` as its alias.** The M3 contract §3 names the CLI as `snowpea setup --login <vendor>`. Both exist in `--help`; `provider login` reads better and groups with `provider list`, so it leads and the alias is mentioned once.

11. **`docs/manual/ja|zh-CN|es/*.md` link out to English for pages they do not have.** Rather than leaving dangling links or stub pages, every cross-reference from a partial-language page to a page that language lacks points at `../en/<page>.md`. Each partial page also carries a language line under its heading. This keeps the link check green without fabricating content.
