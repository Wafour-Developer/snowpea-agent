# US-018 deviations — M6 generators: agent definitions, `/agent`, `/skill learn`

Recorded against `docs/design/m6-m7-skills-agents-contract.md` §2 (that document
stays the contract; this file records where the implementation differs).

Implemented: `core/snowpea_core/agent/definition.py`,
`core/snowpea_core/commands/agent_cmd.py`,
`core/snowpea_core/commands/skill_cmd.py`,
`core/snowpea_core/server/agent_handlers.py`,
`tests/test_generators.py`,
`tests/fixtures/providers/fake/generators.json`.

Subagents (§3), team mode (§5) and named agents (§6) are US-019/020/021's;
`agent.spawn`, `agent.bindChannel`, `agent.delete`, `team.*` stay
`not_implemented`.

## Deviations

1. **The frontmatter parser is hand-rolled.** The project has no YAML
   dependency and adding one for five scalar keys was not worth it, so
   `definition.py` parses the subset §2 needs: `key: value`, inline
   `[a, b]` lists, and `-` block lists. `render_agent_md` quotes any value
   containing a YAML indicator, so the output is also valid YAML and a real
   parser can read it later without a migration.

2. **`AgentDefinition` carries `path` and `source` beyond the §2 field list.**
   `/agent list` and `agent.list` both have to report where a definition came
   from, and §1's loader records the same `source` values
   (`builtin|global|project|plugin:<name>`).

3. **`AgentInfo` gained `kind` and `path`; `AgentCreateResult` gained `path`**
   (additive, protocol regenerated). `kind` defaults to `"definition"`, which
   is all this story returns; US-019 and US-021 add `"subagent"` and
   `"named"` on top. `path` is what the command's reply already prints, so a
   client gets the same thing over RPC.

4. **The listing does its own directory scan and merges the loader's view on
   top of it.** §2 hands registration to the §1 loader, but US-017 was still in
   flight, so `commands/agent_cmd.definitions_for` scans
   `<workdir>/.snowpea/agents`, `<workdir>/.claude/agents` and
   `$SNOWPEA_HOME/agents` itself and merges anything extra the loader knows
   (plugins, built-ins) from `core.skills.agents`. The on-disk scan is
   authoritative for the project and global roots, so the listing is correct
   whether or not `core.skills` exists. `register_agent_definition(path)` and
   `reload()` are called through `getattr`, and a loader that raises is logged
   rather than failing the command.

5. **`commands.changed` is not emitted here.** §1 makes it the loader's
   notification on `reload()`. `/agent create` and `/skill learn` call
   `reload()`, so the event is emitted exactly once, by whoever owns it.

6. **`/skill` only handles `learn`.** `skill.learn` is deliberately not a
   protocol method (§1 lists only `skill.search|install|list|reload`), so
   learning is command-only. The other verbs answer with a pointer to the
   `snowpea skill` CLI, which is US-017's.

7. **`/agent create` ends its turn with `reason: "complete"` even when the
   model's reply is unusable.** The failure is reported as an `error` session
   event plus a `message.done` explaining it, which is what the story asks for;
   `turn.done` stays `complete` because the command itself ran to completion,
   matching every other built-in command in `commands/registry.py`.

8. **Non-ASCII names are rejected rather than transliterated.** `slugify`
   drops characters with no ASCII form, so a Korean brief only works when the
   model answers with an ASCII slug — which is what `GENERATOR_SYSTEM` demands.
   A reply that has no usable name raises `DefinitionError` and writes nothing.

9. **`agent.create` and `agent.list` take no session id** (the protocol models
   are fixed), so the project directory is resolved the way
   `permission.allowlist.*` already does it: the caller's own session, else the
   only open one. `agent.create` without a session is an `invalid_params`
   error; `agent.list` falls back to the daemon's own directory.

## Test status

`tests/test_generators.py` is green in full (11 tests). The last of them,
`test_learned_skill_becomes_a_command`, calls `pytest.xfail` at runtime if
`core.skills` is missing, because a learned SKILL.md can only become `/notes`
once the US-017 loader is wired into `Core`; US-017 landed during this story,
so it now asserts for real.

US-017's `SkillLoader.register_agent_definition(path)` returns a `LoadedAgent`
carrying `name`, `description`, `source` and `path`, which is exactly what
deviation 4's merge step reads, so no adapter was needed.
