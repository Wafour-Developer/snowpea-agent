# Deviations — US-013 (permissions: modes / allowlist / approval queue UI)

Against `docs/design/m1-core-contract.md` §7 and §9, and plan §3.1 / AC-05 / AC-12 / AC-13.
Recorded here rather than appended to the contract, per the lead's note about concurrent
edits losing sections.

1. **allowlist 엔트리는 문자열이 아니라 객체다.** §0이 프로젝트 설정의 `allowlist`를 이름만 적어 두어, `config/project.py`에 `AllowlistEntry{id, pattern, target}`를 정의하고 `ProjectSettings.allowlist`/`Settings.allowlist`를 그 리스트로 바꿨다. `id`가 있어야 `permission.allowlist.remove(patternId)`가 성립한다. 예전 `["^ls.*$"]` 형태(문자열 배열)는 `field_validator(mode="before")`가 `target="shell"` 엔트리로 승격해 읽으므로 기존 파일은 그대로 열린다.
2. **내부 scope는 `project` / `global`, 와이어 scope는 `project` / `always`.** 프로토콜의 `AllowlistScope`는 `session|project|always`인데 저장소는 둘뿐이다. `app_server.WIRE_SCOPE`가 `always → global`, `project`·`session → project`로 매핑하고 `STORE_SCOPE`가 되돌린다. `session`은 영속 저장소가 없어 프로젝트 저장소로 접는다.
3. **`target` 축.** 패턴은 exec 태그 툴(또는 `shell`/`bash`/`run_command`)의 `args.command`에 대해 매칭하는 `target:"shell"`이거나, 툴 이름 자체에 매칭하는 `target:"tool:<name>"`이다. RPC `permission.allowlist.add`는 파라미터에 `target`이 없으므로 항상 `shell`을 쓴다. 툴 단위 예외는 `/allow tool:<name>`으로 만든다.
4. **매칭은 `re.search`.** `^ls( .*)?$`처럼 앵커를 직접 쓰는 계약 예시를 그대로 살리면서 부분 매칭 패턴도 허용한다. 컴파일 불가 패턴은 `add()`가 `invalid_params`로 거부하고, 이미 저장된 깨진 패턴은 매칭에서 무시하고 경고만 남긴다.
5. **승인 세션 캐시 키가 `(sessionId, tool)` → `(sessionId, tool, 명령 첫 토큰)`으로 좁아졌다.** §16-8의 동작이 `ls`를 한 번 허용하면 같은 세션의 모든 셸 명령을 허용하던 문제를 고친다. 셸이 아닌 툴은 토큰이 `""`라 이전과 같다.
6. **`project`·`always` scope 응답이 allowlist를 쓴다.** `ApprovalQueue._persist`가 요청에서 패턴을 만든다: 셸이면 첫 토큰 기준 `^<token>( .*)?$`, 아니면 `tool:<name>`. `project`는 세션 workdir의 `.snowpea/settings.json`, `always`는 `$SNOWPEA_HOME/settings.json`. 중복은 기존 id를 재사용한다.
7. **`permission.allowlist.*`에는 workdir 인자가 없다.** 프로토콜 모델(`extra="forbid"`)을 건드리지 않기로 해서, 핸들러가 호출 연결이 만든 세션의 workdir을 쓰고, 없으면 열린 세션이 정확히 하나일 때 그 세션을, 그것도 아니면 `invalid_params`를 낸다.
8. **핸들러 위치.** §16-1과 같은 이유로 `server/session_handlers.py`가 아니라 `server/app_server.py`의 `register_permission_handlers`에 있다(US-010이 `session_handlers.py`를 동시 편집 중이었다). `build_dispatcher`가 `register_session_handlers` 직후에 부른다.
9. **모드 명령이 `commands/mode_cmd.py`로 이사했다.** `/plan` `/accept` `/auto` `/mode`와 새 `/approvals` `/allow` `/allowlist`가 여기 산다. `commands/builtin.py`에는 `/help` `/tools`만 남고, 옮긴 심볼은 재export 한다. `/mode`는 `show`를 추가로 받는다(`/mode [plan|accept|auto|save|show]`).
10. **프로젝트 기본 모드는 이미 US-005가 구현해 뒀다.** `SessionManager.default_mode()`가 `ProjectSettings.defaultMode`를 읽고, CLI는 `--mode`가 주어졌을 때만 `session.create`에 실어 보낸다(§14-11). US-013은 `/mode save`가 그 값을 쓰는지와 새 세션이 그대로 시작하는지를 테스트로 고정했다.
11. **TUI 승인 큐는 Ctrl+A로 포커스한다.** 단일 키(`a`/`d`)가 채팅 입력줄의 글자를 훔치지 않게 하기 위해, 큐는 포커스를 받기 전까지 읽기 전용이다. 포커스 중에는 ↑/↓로 요청, ←/→로 scope를 고르고 `a` 허용 / `d` 거부, Esc·Ctrl+A로 나간다. 키는 `HelpPanel`에 적혀 있다.
12. **무인 큐는 5초 폴링한다.** 무인 요청은 이 서피스가 보지 못하는 턴에서 생기므로 매달 이벤트가 없다. 큐가 비어 있지 않은 동안만 `approval.list`를 `APPROVAL_POLL_MS`(5000ms)마다 다시 읽고, `approval.resolved`가 오면 즉시 한 번 더 읽는다.
13. **`network`/`send` 더미 툴은 테스트 모듈 안에 있다.** M1 툴 세트에 그 태그를 가진 툴이 없어 매트릭스 15칸을 채울 수 없다. `tools/registry.py`(US-009 소유)를 건드리는 대신 `tests/test_permission_matrix.py`가 부작용 없는 `net_fetch`(network)·`send_message`(send)를 정의하고 기동한 데몬의 레지스트리에 직접 등록한다. 프로덕션 툴 목록은 그대로다.
14. **테스트 픽스처 추가.** `tests/fixtures/providers/fake/permissions.json`(태그별 툴 호출 + `grep`으로 allowlist 비매칭 확인). 기존 `session.json`·`basic.json`은 건드리지 않았다.
